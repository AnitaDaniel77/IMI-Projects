Exercise: Submitting the Form and Confirming the Booking

Scenario

The form already submits to submitAPI, but there's no confirmation page yet - customers currently get no feedback that their booking actually went through. This exercise adds a proper confirmation page and navigates there automatically on success.

Step 1 - ConfirmedBooking component and route

function ConfirmedBooking() {
  return (
    <main className="confirmed-booking">
      <h1>Booking Confirmed!</h1>
      <p>We look forward to seeing you at Little Lemon.</p>
    </main>
  );
}

Real-life example: this page is like a receipt handed over after a purchase - it's not functional in the sense of doing more work, its whole purpose is reassurance that the transaction actually completed.

Step 2 - Navigating with code, not a click

import { useNavigate } from 'react-router-dom';

function submitForm(formData) {
  const navigate = useNavigate();
  // useNavigate gives a function to change routes PROGRAMMATICALLY -
  // different from <Link>, which only navigates on a user click

  if (submitAPI(formData)) {
    navigate('/booking-confirmed');
    // this fires automatically after a successful submission,
    // with no link or button click involved in the navigation itself
  }
}

Real-life example: useNavigate is like an usher walking a guest to their seat automatically once check-in succeeds, versus a signpost (<Link>) that only works if the guest actively decides to walk toward it themselves.

Important structural note

useNavigate() is a hook, so it can only be called inside a component function during render - not inside a standalone helper function like the course's plain submitForm example suggests. In this project's actual code, submitForm needs to live inside App (or wherever it's called from), with useNavigate() called at the top of that component, and the resulting navigate function used inside submitForm.

Step 2 (continued) - Passing submitForm down

Same lifting-state-up pattern as before: submitForm gets defined in a parent component and passed down as a prop through BookingPage to BookingForm, which calls it instead of handling the API call directly itself.

Step 3 - Verifying it works

Submit the form and confirm the URL actually changes to the confirmation route and the confirmation message displays - not just that the console logs something.
