Capstone Project - Reserve a Table Functionality

Exercise: Defining the Bookings Page

Scenario

Right now visitors can't actually reserve a table - this exercise builds the real BookingForm as a controlled component, with Date, Time, Number of guests, Occasion, and a submit button.

Step 1 - Components and routes

Need a BookingPage (the page) that contains a BookingForm (the actual form) - plus confirming the nav and routes can actually reach it.

Step 2 - Form structure, HTML to JSX

<label htmlFor="res-date">Choose date</label>
{/* htmlFor, not for - "for" is a reserved word in JavaScript,
    so JSX renames the HTML attribute to avoid the clash */}
<input type="date" id="res-date" />
{/* self-closing - JSX requires every tag to close itself or
    have a matching closing tag, unlike loose HTML5 */}

Real-life example: htmlFor vs for is like a form that has two different words meaning the same thing depending on which office you're in - same intent, different accepted spelling depending on the "building" (HTML vs JSX) you're standing in.

Step 3 - Connecting state to the form

const [date, setDate] = useState('');
// one state variable per field - each input becomes fully
// "controlled" by pairing it with its own useState

<input
  type="date"
  value={date}
  onChange={(e) => setDate(e.target.value)}
  /* value ties the input to state; onChange updates state on
     every keystroke/change - together these make it controlled */
/>

Real-life example: pairing value and onChange on one field is like a thermostat with both a display and a dial wired to the same number - turning the dial (onChange) updates what's shown (value), and nothing can get out of sync between them.

availableTimes as its own state

const [availableTimes, setAvailableTimes] = useState(['17:00', '18:00', '19:00', '20:00']);
// stored as state (not a hardcoded array in the render) because
// this list needs to change later once it's connected to
// something dynamic - simply hardcoded for now

<select>
  {availableTimes.map((time) => (
    <option key={time} value={time}>{time}</option>
    /* .map() turns the array into a list of JSX elements -
       key={time} helps React track which option is which
       when the list changes later */
  ))}
</select>

Real-life example: keeping availableTimes in state now, even though it's just a fixed list today, is like leaving a parking space open before the delivery truck arrives - the structure is ready for something that will actually change later (an API response), instead of needing to be rebuilt from scratch when that day comes.
