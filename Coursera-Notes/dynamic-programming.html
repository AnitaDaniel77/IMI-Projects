Dynamic Programming and Memoization

Course: Coding Interview Preparation — Module 3

What dynamic programming is

An extension of divide and conquer plus recursion: break a problem into smaller sub-problems, solve them, and store the results for reuse. If a sub-problem comes up again, look up the stored answer instead of recomputing it — that technique is memoization.

Worked example — binary lock combinations

A 6-digit binary lock has 2⁶ = 64 combinations. Instead of computing 2×2×2×2×2×2 in one long chain, split it into two groups: 2×2×2 and 2×2×2 — i.e. 2³ × 2³ = 8 × 8 = 64.

With memoization: compute 2³ once, store it, then reuse that stored result for the second 2³ instead of recomputing — cutting the total work needed.

What kind of problems fit this

Commonly combination or optimization problems:

  • Fibonacci sequence — a combination problem, classic memoization use case
  • Knapsack problem — both a combination and optimization problem

The knapsack problem

Packing for a camping trip: each item has a weight and a value (torch = 1kg/value 1, water = 2kg/value 2, tent = 3kg/value 3). Given a weight limit the knapsack can carry, find the combination of items that maximizes total value without exceeding that limit.

Real-world parallel: resource allocation — given fixed CPU capacity and a set of tasks each with a "cost" and "value," find the best combination of tasks to run.

Dynamic programming payoff: if you've already solved the optimum selection for a 7kg capacity, and the capacity later increases to 10kg, you don't need to rerun that entire computation from scratch — the earlier stored results save time.

Building a dynamic programming solution

  1. Define the objective function — what does "optimum" actually mean for this problem?
  2. Break the problem into smaller steps — often via recursive functions
  3. Structure the solution so the objective can change without rewriting the underlying methods

Key takeaway

Dynamic programming = divide and conquer + recursion + memoization. It shines when sub-problems repeat or overlap across a larger computation — the win comes from never solving the same sub-problem twice.

Interview tip

If a problem sounds like Fibonacci or knapsack — "what's the optimal combination given a constraint," or "this smaller calculation keeps getting reused" — that's the signal to reach for dynamic programming, not just plain recursion. Mentioning memoization explicitly (storing sub-results, checking before recomputing) is usually what separates a working recursive solution from an efficient one in an interview answer.
