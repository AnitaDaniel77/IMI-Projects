Capstone Project - Reserve a Table Functionality

Exercise: Semantic Markup, ARIA Attributes, and Form Labels

Scenario

Three concrete accessibility improvements this time: reviewing semantic markup, adding ARIA attributes, and confirming form labels are properly linked to their inputs.

Step 1 - Semantic markup review

Since semantic HTML was already a focus back in Module 2 (nav, header, main, footer, article for cards), this step is largely already covered in the Little Lemon project - it's a check-back rather than new work.

Step 2 - ARIA attributes

<button
  className="btn-primary"
  aria-label="On Click"
  /* aria-* attributes use hyphen-case even in JSX, unlike
     every other JSX prop which uses camelCase - this is a
     deliberate exception, not an inconsistency to "fix" */
>
  Reserve a Table
</button>

ARIA attributes give assistive technology extra context that plain HTML alone doesn't always convey - aria-label specifically overrides what a screen reader announces for an element, useful when the visible text alone isn't descriptive enough on its own.

Real-life example: aria-label is like a museum placard next to an abstract sculpture - the object itself might not make its purpose obvious, so the label fills in the missing context directly for anyone who needs it.

Step 3 - Labeling forms correctly

<label htmlFor="res-date">Choose date</label>
<input type="date" id="res-date" />
{/* htmlFor="res-date" matches id="res-date" exactly - this
    pairing is what makes clicking the LABEL text focus the
    INPUT automatically, not just visual proximity on the page */}

Tip for checking this works: click directly on a form's label text (not the input itself) - if the cursor jumps into the input field, the label/id pairing is correct. If nothing happens, the htmlFor and id don't actually match.

Real-life example: the label/id link is like a claim ticket matching a coat check tag - the two need the exact same number to connect properly, and if they don't match, you can't retrieve the right coat even though both objects exist.

Pseudocode for an accessibility pass

FOR each interactive element (buttons, links):
    does its visible/accessible text clearly describe its action?
    IF not, add aria-label with clearer wording

FOR each form input:
    confirm a <label> exists
    confirm label's htmlFor EXACTLY matches the input's id

FOR the page structure overall:
    confirm nav, header, main, footer are used instead of generic divs
