Integers

Course: Coding Interview Preparation — Module 2

What an integer is

Holds whole numeric values — no fractions. Can be signed (positive and negative) or unsigned (positive only). Represented in binary, commonly using 4 bytes, though depending on system/language it can be 1, 2, or 8 bytes.

Fractions need a different type

Integers can't represent fractions — that's what decimal/float types are for. Floating-point numbers follow the IEEE 754 standard, a common spec most languages use for representing them consistently.

High-level languages like Python and JavaScript wrap number initialization into this fixed representation automatically — easy to use, but no control over memory optimization.

Memory allocation — statically typed languages

Languages like C++, Rust, Ada, and C let you customize integer size:

  • C++: unsigned short int uses only 2 bytes — meaningful savings at scale for apps with many positive, fraction-free numbers.
  • Rust: supports unsigned 1-byte integers, holding 0–255. Small range, but powerful for something like image processing — storing 8 pixel values for the memory cost of 1 standard integer is a major saving in a CPU-intensive process.

Real-life analogy: like choosing a small padlock for a small box instead of a bank vault lock — using more "size" than the job needs just wastes resources.

Java's Integer wrapper class

Beyond the primitive int, Java offers the Integer wrapper class, giving access to extra methods — string-to-double conversion, comparisons, max/min values, etc. The Integer class is immutable, which makes it thread-safe.

Trade-off: that extra functionality and safety costs memory — an Integer object takes 16 bytes versus a primitive int's smaller footprint.

When to care about this

High-level dynamic typing gets you moving fast but limits memory control. If building something resource-constrained — Arduino, other hobby electronics, or anything memory-premium — the ability to customize integer size can be the difference between functional and non-functional. For apps with generous memory headroom, using integers simply and not worrying about the byte-level detail is often the better trade.
