Coding Interview Preparation

Reading: Pseudocode Step by Step

Why use pseudocode at all

Pseudocode is a legitimate first step in devising a solution - a high-level, code-shaped representation of ideas that highlights what elements a program actually needs, before worrying about real syntax.

Each line forces a pause to consider what's actually required. Crucially, an early decision can constrain a later one - if step 3 settles on a data structure, and step 6 turns out to need several fast lookups, it's far cheaper to revisit step 3 while still in pseudocode than after real implementation has already begun.

Real-life example: pseudocode is like sketching a floor plan before building a house - if you realize the kitchen needs to be bigger while it's still lines on paper, that's a five-minute fix. Realizing the same thing after the walls are built is a completely different, much more expensive problem.

When to actually reach for pseudocode

  • As a beginner, plotting out an approach before coding it
  • As an experienced programmer, wrestling with a genuinely complex problem
  • Conveying a concept to an influential audience - a team, potential clients
  • Signposting work for future maintainers of the code
  • In an interview, specifically to demonstrate reasoning ability

There's no single "correct" pseudocode style

Different organizations have different conventions - pseudocode is really just any textual outline of a program's operation. The style tends to resemble whatever real language the writer is most comfortable in.

Worked example - FizzBuzz

The challenge: iterate 1 to 40, print the number normally, except multiples of 3 print "Fizz", multiples of 5 print "Buzz", and multiples of both print "FizzBuzz".

First attempt - the flawed version

FOR each number from 1 to 40:
    IF number is a multiple of 3:
        print "Fizz"
    IF number is a multiple of 5:
        print "Buzz"
    IF number is a multiple of 3 AND 5:
        print "FizzBuzz"
    ELSE:
        print the number

Writing this out as pseudocode makes the bug visible before any real code exists: using separate IF statements instead of ELSE IF means the number 15 (a multiple of both 3 and 5) would trigger ALL THREE branches - printing "Fizz", then "Buzz", then "FizzBuzz", instead of just one correct output.

Corrected version - using exclusionary conditionals

FOR each number from 1 to 40:
    IF number is a multiple of 3 AND 5:
        print "FizzBuzz"
    ELSE IF number is a multiple of 3:
        print "Fizz"
    ELSE IF number is a multiple of 5:
        print "Buzz"
    ELSE:
        print the number

Two things fixed the bug: using ELSE IF instead of separate IFs (so only ONE branch can ever run per number), and ordering the "both 3 and 5" check FIRST, before the individual checks - otherwise a number like 15 would hit the "multiple of 3" branch and print "Fizz" before ever reaching the combined check.

Real code matching the corrected pseudocode

for number in range(1, 41):
    if number % 3 == 0 and number % 5 == 0:
        print("FizzBuzz")  # checked FIRST - most specific condition wins
    elif number % 3 == 0:
        print("Fizz")
    elif number % 5 == 0:
        print("buzz")
    else:
        print(number)

Tip for this pattern generally: whenever a problem has overlapping conditions (a number can be BOTH a multiple of 3 and 5 at once), always check the most specific/combined condition first, and use elif/else if rather than separate if statements - otherwise multiple branches can fire when only one should.

Real-life example: this ordering rule is like a triage system in an emergency room - the most specific, most urgent condition gets checked and handled first, so a patient with multiple overlapping symptoms doesn't get sorted into the wrong, less-specific queue first.

Who actually uses pseudocode, and when

Not just a beginner tool - junior engineers use it to understand how a program should flow, senior engineers use it to communicate ideas to a team. The style settled on tends to mirror whichever real language the person is most comfortable in.
