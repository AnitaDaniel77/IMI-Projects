Reading: Recap - Forms

Forms behave differently from other DOM elements in React - regular HTML form elements keep their own internal state by default, which clashes with how React normally wants to manage things.

Preventing the default form behavior

function BookingForm() {
  const handleSubmit = (event) => {
    event.preventDefault();
    // stops the browser's default behavior of reloading the
    // page on submit - without this, the form would navigate
    // away and React would lose all its state instantly
  };

  return (
    <form onSubmit={handleSubmit}>
      <input type="number" />
      <button type="submit">Book</button>
    </form>
  );
}

Real-life example: preventDefault() is like intercepting a letter before it gets mailed - the browser's default instinct is to "submit and reload," but this stops that instinct so you can decide what actually happens with the data instead.

Controlled components

function ControlledInput() {
  const [guests, setGuests] = useState(1);

  return (
    <input
      type="number"
      value={guests}
      onChange={(e) => setGuests(e.target.value)}
      // every keystroke updates state, and state is what's
      // actually displayed - React owns the value entirely
    />
  );
}

Real-life example: a controlled component is like a live order ticket at a restaurant kitchen - the second a customer changes their order, the ticket on the wall updates instantly. There's never a gap where the ticket and the actual order disagree.

Uncontrolled components

function UncontrolledInput() {
  const guestsRef = useRef(null);

  const handleSubmit = (event) => {
    event.preventDefault();
    console.log(guestsRef.current.value);
    // reads the value directly from the DOM only at the
    // moment it's needed - React isn't tracking it as state
    // the whole time
  };

  return (
    <form onSubmit={handleSubmit}>
      <input type="number" ref={guestsRef} />
    </form>
  );
}

Real-life example: an uncontrolled component is like a suggestion box - people write things down without anyone watching in real time, and you only check the box's contents when you actually open it. The information exists the whole time, just not tracked continuously.

Which to use

Uncontrolled components can help when integrating React with other front-end libraries that expect direct DOM access. That said, the official React docs recommend controlled components as the default approach most of the time.
