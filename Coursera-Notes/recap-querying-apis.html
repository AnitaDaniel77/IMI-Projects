What JSON actually is

JSON (JavaScript Object Notation) is a data interchange format and file extension - not unique to React at all. Any Node.js project has a package.json, and that file is a real, everyday example of JSON syntax already sitting in every project.

Real-life example: JSON is like a shipping label format used across every courier company - it's not something React invented, it's just a common, agreed-upon way to package data so anything can read it, the same way a shipping label format works no matter which company printed it.

fetch() as a side effect

// A side effect = anything happening OUTSIDE React itself
console.log('side effect');       // side effect
document.title = 'New title';    // side effect
fetch('https://api.example.com'); // side effect

Because fetch() reaches outside React's own rendering system to talk to a real server, it has to run inside useEffect - not directly in the component body.

Real-life example: side effects are like a waiter stepping outside the restaurant to grab something from a delivery truck - it's necessary, but it's clearly a separate action from serving tables (rendering), which is why it needs its own designated moment (useEffect) rather than happening in the middle of everything else.

What to do once data arrives

useEffect(() => {
  fetch('https://api.example.com/times')
    .then((res) => res.json())
    .then((data) => setAvailableTimes(data));
    // 1. update state with the received data
}, []);

return (
  <select>
    {availableTimes.map((time) => (
      <option key={time}>{time}</option>
      // 2. loop over the data (usually with .map()) to actually
      //    render something from it
    ))}
  </select>
);

.map() being the go-to looping tool is exactly why data arriving as an array of objects is so convenient - it's the shape .map() is built for.

A simpler local approach

// Instead of fetching from a real server while prototyping,
// just define the data as a plain JS array and import it directly
export const availableTimes = ['17:00', '18:00', '19:00', '20:00', '21:00'];

This is essentially what's already been done in this project so far - the hardcoded array in initializeTimes() is exactly this "simpler approach," standing in for a real API call during early development. No side effects, no useEffect needed, no network dependency - ideal for prototyping before the real API integration is built.

Real-life example: this is like rehearsing a play with placeholder props before the real set pieces arrive - the actors (the rest of the app) get to practice their actual lines and blocking without needing the real, more complicated equipment to be ready yet.
