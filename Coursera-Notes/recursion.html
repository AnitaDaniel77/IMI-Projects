Recursion

Course: Coding Interview Preparation — Module 3

What recursion is

A function that calls itself with a smaller version of the problem, repeatedly, until an exit condition is met — an alternative to using a loop.

Three requirements

  1. Base case: the condition that stops the function from calling itself again
  2. Diminishing structure: the input must shrink with each call, so it actually reaches the base case eventually
  3. Recursive call: the function calling itself, passing in the reduced input

Worked example — exponentiation

function power(x, n):
    if n == 0:          // base case
        return 1
    return x * power(x, n - 1)   // recursive call with diminished n

Calling power(2, 3) creates three stacked instances on the call stack before resolving back down. Each function call has a real computational cost — more overhead than a plain loop — but the trade-off can be worth it (see below).

Binary search as recursion

Binary search naturally fits recursion: check the midpoint, then recursively search whichever half the target falls in, until found or the search space is empty. Same logic as the loop-based version, just expressed as self-calls instead of iteration.

Why choose recursion over a loop

  • Readability: some problems (like Fibonacci) turn into much cleaner code recursively than as a sprawling loop with lots of manual state tracking.
  • Retained history: each call stays on the call stack with its own state, which is useful for hierarchical problems or anything where knowing "how did we get here" matters — like traversing a graph or tree.
  • Natural fit for divide and conquer: recursion is often how divide-and-conquer solutions are actually implemented — break the problem down, solve the smallest piece, let the calls unwind back into a full solution.

Fibonacci example

Sequence where the first two numbers are 0 and 1, and every subsequent number is the sum of the previous two. Recursive definition:

function fib(n):
    if n <= 1:
        return n
    return fib(n-1) + fib(n-2)

Interview tip

If a problem description sounds like "do X, then do X again on a smaller piece" — binary search, tree/graph traversal, Fibonacci, factorial — recursion is likely the expected approach. Always state the base case first when talking through a recursive solution out loud; interviewers listen for that as confirmation you understand why the recursion terminates.
