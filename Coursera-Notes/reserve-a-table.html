Lesson: Introducing the Reserve a Table Functionality

This lesson covers three React concepts needed to build the actual booking feature: state, forms, and unit tests.

Why state matters

Without state, components would just be a way to split one big HTML page into smaller, easier-to-read chunks - useful for organization, but with zero interactivity. State is what makes a component actually respond to what a user does, rather than just display fixed content. Components and state are described as "inextricably linked" in modern React - one without the other loses most of the point.

Real-life example: a component without state is like a printed menu - readable, organized, but it can't change no matter what the customer does. State is what turns that menu into something a waiter can actually update in response to what's ordered.

The classic counter example

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  // count = the current value; setCount = the only way to change it

  return (
    <div>
      <p>{count}</p>
      <button onClick={() => setCount(count + 1)}>+</button>
      {/* clicking calls setCount, which triggers a re-render
          showing the new value */}
    </div>
  );
}

This simple example is used constantly in teaching because it touches rendering, the useState hook, and event handling all at once - the same three pieces needed for the actual booking form.

Controlled vs. uncontrolled form components

// Controlled: React's state IS the source of truth for the input's value
function ControlledInput() {
  const [name, setName] = useState('');
  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
      /* every keystroke updates state, and state drives what's shown */
    />
  );
}

// Uncontrolled: the DOM itself holds the value, React just reads it when needed
import { useRef } from 'react';

function UncontrolledInput() {
  const inputRef = useRef(null);
  // ref gives direct access to the actual DOM node, bypassing state

  const handleSubmit = () => {
    console.log(inputRef.current.value); // read the value only when needed
  };

  return <input ref={inputRef} />;
}

Real-life example: a controlled input is like a live scoreboard that updates the instant a point is scored - React's state and the display are always in sync. An uncontrolled input is like a tally sheet on a clipboard - the real record lives on the paper (the DOM) itself, and you only check it when you actually need the number.

Why unit tests matter here

The core questions this lesson raises: how do you know the app actually meets requirements, and how do you know new features haven't broken something that used to work? Unit tests are the answer to both - a way to verify behavior automatically, rather than manually re-checking everything by hand every time something changes.

A note on difficulty

The lesson explicitly flags that combining state, forms, and testing together isn't trivial, and recommends budgeting real time for it - plus revisiting earlier course material if needed.
