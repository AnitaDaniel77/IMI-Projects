Capstone Project - Reserve a Table Functionality

Exercise: Heuristic Evaluation Using Nielsen's 10 Heuristics

Scenario

An abridged heuristic evaluation of the actual Little Lemon reserve-a-table app, using Nielsen's 10 usability heuristics. The goal isn't a precise diagnosis - it's spotting where users might struggle to find information, complete tasks, or use the site effectively.

Step 1 - Template 1: usability problems + severity

Severity scale:

  • S0 - violates a heuristic, but not really a usability issue
  • S1 - cosmetic, easily overcome, low priority
  • S2 - minor, more frequent/harder to overcome, low priority
  • S3 - major, frequent and persistent, high priority to fix
  • S4 - catastrophic, blocks use entirely, must fix before release

Step 2 - Template 2: same heuristics, easy-to-fix rating

  • E0 - maximum effort, needs more investigation
  • E1 - considerable effort, but solution is understood
  • E2 - concentrated effort, solution is understood
  • E3 - easy, single developer, minor effort
  • E4 - trivial to implement

Pseudocode for running this evaluation properly

FOR each of Nielsen's 10 heuristics:
    walk through EVERY screen of the app with that ONE heuristic in mind
    IF a violation is found:
        write down the specific problem (not just "fails heuristic X")
        assign a severity rating (S0-S4)
        assign an easy-to-fix rating (E0-E4)

Tip: a good usability problem description names the exact screen, the exact action, and what a user would actually experience - "the submit button is disabled with no visible reason why" is useful; "form has issues" is not specific enough to act on.
