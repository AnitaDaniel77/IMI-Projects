Searching Algorithms — Linear and Binary Search

Course: Coding Interview Preparation — Module 3

Why searching needs care

Searching a dataset sounds simple, but the exact question matters — a key-value lookup, largest/smallest value, median value — each shapes the approach. A key design question: what happens if nothing matches? Returning null can break downstream code, so safeguards matter. (Tony Hoare, who invented the null reference, has called it his "billion-dollar mistake.") Also worth deciding upfront: does the search return the first match or the last?

Linear search

Start at the beginning of the array, check each element in order until found or the array ends.

  • Best case: O(1) — target is the first element
  • Worst case: O(n) — target is last, or absent entirely (every element must be checked to confirm)

No requirement that the data be sorted.

Binary search

Requires sorted data. Checks the midpoint, compares to the target, and discards the half that can't contain it — repeating on the remaining half each time.

low = 0, high = n - 1
while low <= high:
    mid = (low + high) / 2
    if target == array[mid]: return mid
    elif target < array[mid]: high = mid - 1
    else: low = mid + 1
  • Best case: O(1) — target found on the first check
  • Worst case: O(log n) — search space halves each iteration until one element remains

Real-life analogy: looking up a word in a printed dictionary — you don't start at page 1, you flip to roughly the middle and narrow left or right from there.

The catch — sorting has a cost

Binary search is faster than linear once the data's sorted, but sorting itself isn't free. It's worth it when data is read far more often than it's updated — sort once, search many times. If the data changes frequently, repeatedly re-sorting to keep binary search viable can outweigh the search speed gained.

Interview tip

If asked "how would you search this data faster," the real answer often isn't "use binary search" alone — it's "is this data sorted, and if not, is sorting it once worth the cost given how often we'll search versus update it?" That trade-off reasoning is usually what's being tested.
