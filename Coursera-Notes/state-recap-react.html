Reading: Recap - State in React

State is the foundation of making React apps interactive - same for the actual table booking feature. State is an object, controlled through the useState hook.

Object destructuring

import React, { useState } from "react";
// pulling useState out of the React object directly, so you
// can write useState() instead of React.useState() everywhere
// else in the file

Real-life example: object destructuring is like being handed a toolbox and only taking out the screwdriver you actually need, instead of carrying the whole box around every time you want to use one tool.

Array destructuring of useState

const [tasks, setTasks] = useState();
// useState always returns an array with exactly 2 items:
// [currentValue, functionToUpdateIt] - you can name them
// anything you want, since array destructuring goes by
// POSITION, not by matching a specific key name

Real-life example: array destructuring is like unpacking a delivery box by position - "first item goes on the left shelf, second item goes on the right shelf" - regardless of what the items are labeled inside. Object destructuring, by contrast, is like a delivery where each item is labeled and you have to grab the one with the matching name.

Initial state as an array of objects

const [tasks, setTasks] = useState([
  { id: 1, task: "Go shopping", done: true },
  { id: 2, task: "Wash dishes", done: false },
]);

An array of objects is convenient because it makes create/read/update/delete operations on individual items straightforward - and it's such a common pattern that many real APIs return data shaped exactly like this.

Real-life example: this is like a restaurant's order board - each order is its own card (an object) with its own details, and all the cards together form one list (the array) that's easy to scan, add to, or cross items off of.

Passing state down as props

return (
  <TaskList tasks={tasks} />
  // the tasks array (state) gets handed down to TaskList as
  // a prop - TaskList itself never touches useState directly,
  // it just receives the data and displays it
);

Real-life example: this is like a manager (the parent component) handing a prepared report (state) to an assistant (the child component) to read out loud - the assistant doesn't write the report, just presents what was handed to them.
