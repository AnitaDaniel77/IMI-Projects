Strings

Course: Coding Interview Preparation — Module 2

What a string is

An ordered sequence of characters encased in matching single or double quotes. Most languages support ASCII (1 byte per character) and Unicode (variable bytes depending on encoding — UTF-8, UTF-16, etc).

Common operations

All languages support creating, copying, and assigning strings. Whether they can be modified in place depends on mutability (see below). Everyday operations: concatenation, appending, finding a substring, working with collections of strings.

Many languages allow algebraic-style comparisons: String_A == String_B (true/false), String_A < String_B (alphabetical ordering).

Some languages (PHP) allow variables embedded directly in strings; others (JavaScript) require curly braces: {variable}.

Escape characters

Backslash \ lets you include special symbols — like quotation marks — inside a string without ending it early:

String = "the man said \"two more pints please\" to the barman"

Other common escape symbols: #, %, ', or a double quote nested inside a string wrapped in single quotes.

Tokenization

Converting a string into an array of smaller strings by splitting on a delimiter. E.g. splitting a paragraph into sentences using ., or a sentence into words using a space.

Watch out for false delimiters — the sentence "At 3.30 I went to the shop and spent $40.40." has three periods, but only one is a genuine sentence-ending delimiter; the other two are inside a time and a currency amount.

Tokenizing structured, formatted data (CSV, TSV) is more predictable — this is called parsing. The returned array size equals the number of delimiters found, with the delimiters themselves removed. The newline character also acts as a delimiter unless stated otherwise (each row = new entry).

Immutability

Mutable: a string can be changed after creation (Ruby, PHP).
Immutable: a string cannot be changed after creation — more common (Java, C#, JavaScript, Python, Go).

Why immutability is common: memory savings via a string pool. Instead of every variable holding its own copy of a string's data, all instances of an identical string point to one shared location. Change "string" to "strings" and the variable doesn't overwrite the original — it gets pointed at a different (or newly pooled) immutable instance.

Real-life analogy: like a library with one copy of a book that many readers reference, instead of printing a new copy for everyone who wants to read it — cheaper, as long as nobody needs to scribble in their own copy.

Trade-off: if an application constantly changes text, every alteration pays a memory penalty (a new pooled instance each time), so immutability is a win for read-heavy use, a cost for write-heavy use.

Common real-world usage

Natural Language Processing (NLP) deals heavily with strings — reading text from Twitter, PDFs, text documents, Reddit, etc. Unusual symbol encodings from these sources can cause subtle, hard-to-debug issues if not handled carefully.
