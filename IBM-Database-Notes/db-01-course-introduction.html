Java Development with Databases: Course Introduction

Course 8 of the IBM Java Developer Professional Certificate. Four modules of about 3 to 4 hours each, plus a final project and final exam.

Acronyms

  • SQL: Structured Query Language, the language used to ask a relational database for data or change it.
  • JDBC: Java Database Connectivity, Java's built-in way to connect to a database and run SQL.
  • JPA: Java Persistence API (Application Programming Interface), a standard for mapping Java classes to database tables.
  • ORM: Object-Relational Mapping, turning table rows into Java objects and back without writing all the SQL yourself.
  • CRUD: Create, Read, Update, Delete, the four basic things you do with data.
  • NoSQL: "Not only SQL", databases that don't store data in tables with fixed columns.
  • REST: Representational State Transfer, an API style using GET, POST, PUT and DELETE.

Why databases matter

Almost every real app stores data in a database, from banking systems to social media. A Java developer needs to connect to databases, read and write data efficiently, and keep it working as the app grows.

Real-life example: the Capitec app is only useful because every balance, transaction and beneficiary is stored safely in a database behind it.

Module 1: Fundamentals of databases and JDBC

Relational database basics, database design, connecting Java to a database with JDBC, and doing CRUD in code.

Real-life example: a relational database is like a set of linked spreadsheets. A Clients table and an Accounts table are joined by the client's ID.

Module 2: Spring Boot for database applications

Configuring Spring Boot with a database, using Spring Data JPA for CRUD, and exposing that data through REST APIs.

Real-life example: Spring Data JPA is like a filing clerk. You say "save this client" or "find client 42", and the clerk handles the filing cabinet for you.

Module 3: Hibernate and other databases

Hibernate as an ORM framework, entity relationships, caching, query optimisation, and other kinds of storage: NoSQL (MongoDB), graph (Neo4j) and time series (InfluxDB).

  • MongoDB stores documents (JSON-like records), so it's good for flexible data.
  • Neo4j stores nodes and connections, so it's good for relationships like "who sent money to whom".
  • InfluxDB stores readings over time, so it's good for things like server metrics every second.

Real-life example: caching is like a teller keeping the most-used forms on the desk instead of walking to the storeroom every time.

Module 4: Final project

Acting as a back-end developer for a warehouse distribution company that supplies retail stores. You'll build the back end with Java, Spring Boot and Hibernate, using MySQL plus MongoDB, for admin users who:

  • create and maintain store records
  • manage the product catalogue
  • monitor stock levels
  • place customer orders
  • run SQL procedures to analyse sales and inventory

Pseudocode: how a Java app talks to a database


OPEN a connection using URL, username, password
PREPARE an SQL statement with placeholders
FILL IN the placeholder values
RUN the statement
IF it was a SELECT
    LOOP through each result row
        read the columns into a Java object
CLOSE the connection

Tips for understanding the logic

  • The course builds up in layers: plain JDBC first, then JPA and Hibernate, which write most of that JDBC for you.
  • Learn the plain JDBC steps well, so you understand what Spring is doing behind the scenes later.
  • Always use placeholders (?) in SQL instead of joining strings, to protect against SQL injection.
  • This links straight to your IMI evaluation project and PayNest work, which both need data that survives a restart.
