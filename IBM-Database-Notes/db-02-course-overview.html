Java Development with Databases: Course Overview

Planned for 4 weeks, one module per week. Prerequisites (all done): Intro to Software Engineering, Java Programming for Beginners, Spring Framework for Java Development, plus Git and GitHub.

Acronyms

  • CRUD: Create, Read, Update, Delete.
  • JDBC: Java Database Connectivity, Java's built-in way to run SQL against a database.
  • JPA: Java Persistence API, the standard for mapping Java classes to tables.
  • ORM: Object-Relational Mapping, rows become objects and objects become rows.
  • SQL: Structured Query Language, works on tables and columns.
  • HQL: Hibernate Query Language, like SQL but written against Java class and field names instead of table and column names.
  • NoSQL: databases without fixed tables, like MongoDB.
  • REST: an API style using GET, POST, PUT and DELETE.
  • CLI: Command Line Interface, typing commands in a terminal instead of clicking.
  • MySQL: a popular free relational database.

Course objectives

  • Understand databases and their role in apps.
  • Do basic CRUD with JDBC.
  • Create and tune connection pools.
  • Use Spring Boot abstraction to make database work simpler.
  • Expose CRUD through REST APIs.
  • Understand JPA and configure Hibernate in Spring Boot.
  • Handle entity relationships (one-to-many, many-to-many) with Hibernate.
  • Know the difference between HQL and SQL.
  • Do CRUD with NoSQL databases and configure them in Spring Boot.

Connection pools

Opening a database connection is slow. A connection pool opens a few connections up front and lends them out, so each request doesn't have to open a new one.

Real-life example: a branch keeps a few pens chained at the counter. Clients borrow one and give it back, instead of every client being handed a brand-new pen.

Abstraction

Your code talks to an interface like ClientRepository with methods such as save and findById. What's behind it can change (a HashMap, JDBC, JPA, MongoDB) without touching the code that uses it. This is Dependency Inversion again, from the SME session.

Real-life example: you deposit money at any Capitec branch the same way, even though the systems behind the counter may differ.

SQL vs HQL

SQL: SELECT * FROM client WHERE client_name = 'Anita' (table and column names).

HQL: FROM Client c WHERE c.name = 'Anita' (class and field names).

Real-life example: SQL asks the filing cabinet by drawer label, while HQL asks by the client's name as you know it in the app.

Modules

  1. Fundamentals of databases and JDBC: design basics, connections, CRUD in code.
  2. Spring Boot for database apps: configuration, Spring Data JPA, REST APIs.
  3. Hibernate and other databases: relationships, caching, query optimisation, NoSQL, graph and time series databases.
  4. Final project: the back end for an admin-only retail management system with Java, Spring Boot, Hibernate, MySQL (structured data) and a NoSQL database (unstructured data).

Pseudocode: the same CRUD at different layers


APP CODE:   repository.save(client)
                |
INTERFACE:  ClientRepository (save, findById, update, delete)
                |
BEHIND IT (pick one, app code doesn't change):
    in-memory  -> put in a HashMap
    JDBC       -> run INSERT INTO client ...
    JPA        -> entityManager.persist(client)
    MongoDB    -> insert a document

Tips for understanding the logic

  • Every topic in this course is CRUD done a different way. Map each new tool back to Create, Read, Update and Delete.
  • Structured data with fixed fields (orders, stores) goes in MySQL. Flexible or changing data (product reviews, logs) suits NoSQL.
  • Write to the interface first, then plug in the implementation.
