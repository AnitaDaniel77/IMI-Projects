SQL: DDL, DML and Procedures

Acronyms

  • SQL: Structured Query Language, the standard language for relational databases.
  • DDL: Data Definition Language, commands that build or change the structure (tables).
  • DML: Data Manipulation Language, commands that work with the data inside tables.
  • DQL: Data Query Language, just SELECT, for reading data. It's often grouped with DML.

DDL: building the structure

  • CREATE: make a new table or other object.
  • ALTER: change an existing table, like adding a column.
  • DROP: delete a table completely, structure and data.

In the bookstore example, CREATE makes a Books table with book_id (primary key), title (NOT NULL, so it can't be empty), author and price. ALTER ... ADD adds a publication_year column, and DROP removes the whole table.

Real-life example: DDL is building and renovating the filing cabinet. CREATE builds it, ALTER adds a new drawer, and DROP throws the whole cabinet out.

DML: working with the data

  • INSERT: add a new row.
  • UPDATE ... SET ... WHERE: change existing rows.
  • DELETE ... WHERE: remove rows.
  • SELECT ... WHERE: read rows. WHERE acts as the filter.

Real-life example: DML is what happens to the files inside the cabinet. Opening a new client file is INSERT, changing a cellphone number is UPDATE, closing an account is DELETE, and looking a client up is SELECT.

Stored procedures

A reusable set of SQL statements saved inside the database, like a function in Java. It can take inputs, do the work and return a result. You create it with CREATE PROCEDURE and run it with CALL.

Why use them:

  • Automate repeated jobs, like monthly reports.
  • Keep complex business logic in one place, like discounts or validation.
  • Better performance, because less data travels between the app and the database.

Real-life example: month-end interest. Instead of the app pulling every account, working out interest and sending it all back, one procedure inside the database does it in a single call.

Real-world uses

  • University: DDL to set up Students, Courses and Enrolments, and ALTER to update course details.
  • E-commerce: DML to insert orders, delete cancelled ones and update delivery status.
  • Banking: a procedure that calculates monthly interest by account type and rate.

Pseudocode: the bookstore lifecycle


DDL
    CREATE table Books (id PK, title required, author, price)
    ALTER Books ADD publication_year

DML
    INSERT a new book
    UPDATE price WHERE id = 1
    SELECT books WHERE author = 'X'
    DELETE book WHERE id = 2

PROCEDURE
    CREATE total_book_value: SELECT SUM(price) FROM Books
    CALL total_book_value

Tips for understanding the logic

  • DDL changes the shape of the table. DML changes what's inside it.
  • Always use WHERE with UPDATE and DELETE. Without it, every row gets changed or deleted.
  • DROP TABLE deletes everything and can't be undone. DELETE without WHERE empties the table but keeps its structure.
  • A stored procedure is just a saved method that lives in the database instead of in your Java code.
