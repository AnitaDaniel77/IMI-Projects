More SQL

Acronyms

  • SQL: Structured Query Language.
  • CTE: Common Table Expression, a named temporary result you define with WITH and then use like a table.
  • DESC / ASC: descending (biggest first) and ascending (smallest first).

GROUP BY and HAVING

GROUP BY puts rows with the same value into one group, so you can total, count or average each group. HAVING filters those groups after they've been totalled. WHERE filters single rows before grouping.

Example: total sales per product gives Laptop 2200 and Smartphone 1200. Adding HAVING SUM(Amount) > 1500 keeps only Laptop.

Real-life example: GROUP BY is sorting the day's transactions into a pile per branch and adding up each pile. HAVING is then keeping only the branches that did more than R1 million.

ORDER BY

Sorts the results. ORDER BY TotalSales DESC puts the biggest first.

Real-life example: a leaderboard of top-performing consultants.

Joins

  • INNER JOIN: only rows that match in both tables. Customers who placed orders gives Alice and Bob.
  • LEFT JOIN: every row from the left table, plus the match if there is one, otherwise NULL. Charlie shows with NULL because he has no orders.
  • SELF JOIN: a table joined to itself, using two aliases. Employees and their managers come from the same table.

Real-life example: INNER JOIN is clients who have a loan. LEFT JOIN is all clients, with their loan if they have one. SELF JOIN is a staff list where each person's team leader is also on the same list.

Subqueries

A query inside another query. The inner one runs first and its result feeds the outer one. Example: find the IDs with orders over 600, then get those customers' names, which gives Bob.

Real-life example: first get the list of accounts flagged for fraud, then pull the clients who own those accounts.

Window functions

They calculate across related rows but keep every row, unlike GROUP BY, which squashes rows together.

  • ROW_NUMBER() OVER (ORDER BY Amount DESC) numbers rows 1, 2, 3 by amount.
  • SUM(Amount) OVER (PARTITION BY Region) shows each row with its region's total next to it.

Real-life example: every consultant's sales listed individually, with their branch total in an extra column beside each name.

CTEs

WITH name AS (query) creates a named, temporary result that only exists for that one statement. It makes complex queries readable, avoids repeating subqueries, and supports recursive queries for tree data like org charts. You can chain several CTEs, such as RegionalSales and RegionalTargets, then join them.

Real-life example: doing the rough calculations on a scratch pad first, giving each one a name, then writing the final report from those named results.

Mistakes in the reading

  • The PARTITION BY output only shows 3 rows and says West is 1200. There are 4 rows, and West is 1200 + 700 = 1900.
  • The regional targets output also says West 1200 when it should be 1900.
  • The ROW_NUMBER example selects Name from Orders, but Orders has no Name column, so it needs a join to Customers. Also, Rank is a reserved word in MySQL 8, so use a different alias like RowNum.

Pseudocode: GROUP BY then HAVING then ORDER BY


FOR each sale
    add amount to its product's running total
FOR each product total
    IF total > 1500 keep it (HAVING)
SORT kept totals from biggest to smallest (ORDER BY DESC)

Pseudocode: LEFT JOIN


FOR each customer
    found = false
    FOR each order
        IF order.customerId == customer.id
            print name and amount, found = true
    IF not found
        print name and NULL

Tips for understanding the logic

  • SQL runs in this order: FROM and JOIN, then WHERE, GROUP BY, HAVING, SELECT, and ORDER BY last. That's why HAVING can use SUM but WHERE can't.
  • If you see NULLs after a join, you used a LEFT JOIN and some rows had no match.
  • GROUP BY reduces the number of rows. Window functions don't.
  • Read a subquery from the inside out.
