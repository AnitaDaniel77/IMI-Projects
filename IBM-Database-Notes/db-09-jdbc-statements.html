JDBC Statements in Java

Acronyms

  • JDBC: Java Database Connectivity.
  • ASC / DESC: ascending (A to Z, small to big) and descending (big to small).
  • NULL: no value at all. It's not 0 and not an empty string, it's "unknown".

Statement and ResultSet

A Statement sends SQL to the database. executeQuery() is for SELECT and returns a ResultSet. executeUpdate() is for INSERT, UPDATE, DELETE and CREATE, and returns how many rows changed.

A ResultSet is a cursor over the rows. next() moves to the next row and returns false when there are none left. getInt, getString and getDouble read a column from the current row by name.

Real-life example: a ResultSet is like a printed statement where your finger points at one line. next() moves your finger down one line, and the getters read the columns on that line.

WHERE: filtering

Only returns rows that match a condition, like books by "Author X".

Real-life example: searching transactions for one merchant instead of reading the whole history.

ORDER BY: sorting

ORDER BY Price DESC puts the most expensive first. ASC is the default. With two columns, like ORDER BY Price DESC, Title ASC, it sorts by price first and then by title for books with the same price.

Real-life example: sorting a payment list by amount, then alphabetically when two amounts match.

LIMIT: top lists and paging

LIMIT 5 returns only 5 rows. Combined with ORDER BY, you get a top 5 list. SQL Server uses TOP 5 instead.

Real-life example: "your last 10 transactions" on the app home screen.

GROUP BY with COUNT, SUM and AVG

Groups rows with the same value and calculates per group, like COUNT(*) of books per author. Useful for summary reports.

Real-life example: number of accounts opened per branch this month.

JOIN

INNER JOIN ... ON combines rows from two tables where the linking columns match, like Books.PublisherID = Publishers.PublisherID.

Real-life example: showing each debit order with the company name, by matching the company ID.

IS NULL and IS NOT NULL

Find rows with a missing value (IS NULL) or with a value (IS NOT NULL). You can't use = NULL, because it never matches.

In Java, getDouble() returns 0.0 for a NULL column, so call wasNull() straight after to check whether it was really empty or really 0.

Real-life example: a client with no cellphone number on file isn't the same as a cellphone number of 0. NULL means "not captured yet".

Error handling

Wrap database code in try-with-resources and catch SQLException. getMessage() explains the problem, getSQLState() gives a standard code, and getErrorCode() gives the database's own code. Those are useful for searching for the error.

Statement vs PreparedStatement

A plain Statement is fine for fixed SQL. When values come from a user, use PreparedStatement with ? placeholders, so input can't change the SQL (SQL injection).

Pseudocode


OPEN connection, CREATE statement
RUN query -> get ResultSet
WHILE resultSet.next() is true
    read columns from current row
    print them
IF anything fails
    CATCH SQLException, print message and codes
connection and statement close automatically

Tips for understanding the logic

  • The cursor starts before the first row, which is why you call next() before reading.
  • Column names in getString("Title") must match the SELECT or an alias, otherwise you get an SQLException.
  • SELECT means executeQuery. Anything that changes data means executeUpdate.
  • Use IS NULL, never = NULL.
