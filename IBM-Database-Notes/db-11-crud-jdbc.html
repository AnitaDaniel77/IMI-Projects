CRUD Operations using JDBC

Acronyms

  • CRUD: Create, Read, Update, Delete, the four basic things any app does with data.
  • JDBC: Java Database Connectivity.
  • OFFSET: how many rows to skip before LIMIT starts counting.

The bookstore example

  • Create: add new titles.
  • Read: search by title, author or genre.
  • Update: change prices for promotions.
  • Delete: remove out-of-print books.

The Books table has BookID, Title, Author, Price, Genre, PublicationDate and PublisherID.

Real-life example: CRUD on client records is opening an account, looking a client up, updating their address and closing an account.

Connecting first

Use DriverManager.getConnection(url, user, password) inside try-with-resources, and catch SQLException if the connection fails.

Create: three ways

  • Statement: values typed straight into the SQL. Easy to read, but open to SQL injection. Only use it for fixed values.
  • PreparedStatement: ? placeholders filled with setString, setDouble, setDate and setInt. Secure and reusable.
  • CallableStatement: runs a stored procedure (AddBook) with the same set methods. Use it when the insert logic lives in the database.

PreparedStatement runs SQL directly, while CallableStatement runs a saved procedure. Otherwise the Java code looks almost the same.

Real-life example: Statement is a teller writing whatever the client says on a blank page. PreparedStatement is a proper form with boxes. CallableStatement is sending the form to head office, which has its own process.

Read

  • All books: SELECT with a plain Statement is fine, because there's no user input.
  • By genre: PreparedStatement with WHERE Genre = ?.
  • Pagination: ORDER BY Price DESC LIMIT ? OFFSET ?. Page 1 skips 0 rows, and page 2 skips one page's worth.

Real-life example: the app shows 10 transactions at a time, and "Load more" fetches the next 10 by skipping the first 10.

Update

UPDATE Books SET Price = ? WHERE Title = ?. executeUpdate() returns how many rows changed, and 0 means nothing matched.

Real-life example: changing the interest rate on one product, not every product.

Delete

DELETE FROM Books WHERE Genre = ? removes every book in that genre. Always include WHERE.

Real-life example: closing all dormant accounts of one type, not every account in the bank.

Best practices

  • Handle exceptions gracefully with try-catch around database calls.
  • Manage resources with try-with-resources, so connections, statements and result sets close.
  • Log errors with messages that explain what failed.
  • Validate input before running queries, like a blank title or a negative price.
  • Prefer PreparedStatement whenever any value comes from outside.

Pseudocode: pagination


offset = (page - 1) * pageSize
QUERY books ORDER BY price DESC LIMIT pageSize OFFSET offset
FOR each row
    print title and price

Pseudocode: safe create


IF title is blank OR price is negative
    show message, stop
PREPARE insert with 6 placeholders
SET each placeholder
RUN executeUpdate
PRINT rows added

Tips for understanding the logic

  • Match each CRUD letter to its method: Create, Update and Delete use executeUpdate, and Read uses executeQuery.
  • Check the number executeUpdate returns. It tells you whether anything actually happened.
  • Page 1 means OFFSET 0. Off-by-one mistakes here are common.
  • Statement is only for SQL that never contains outside values.
