git-04: GitHub Repositories

What this lesson covers

How to sign up for a GitHub account and verify it, what a repository holds, the difference between private and public, and what each tab in a new repository is for.

Signing up for a free personal account

  1. Go to github.com.
  2. Choose a username, enter an email address and a password, then click "Sign up for GitHub".
  3. Click Verify and solve the puzzle that proves I'm a person.
  4. Click "Join a free plan" and choose the account type. A free personal account is the default and is what most people need.
  5. Answer the questions about work, programming experience and interests, or skip them.
  6. Open the email GitHub sends and confirm it. This proves the address is really mine.

Real-life example: opening a bank account. You give your details, prove who you are, and confirm through a message sent to your own phone or email before the account becomes usable.

What happens after sign-up

GitHub offers starting points: create a repository, create an organization, or take the Introduction to GitHub course. You can also skip all of it and get to work.

A repository is a data structure for storing documents, including application source code, that tracks and maintains version control. An organization is a collection of user accounts that owns repositories. It has one or more owners with administrative privileges.

Real-life example: a repository is one project folder in a filing cabinet, and an organization is the whole company that owns the cabinet, with a few managers who control who gets keys.

What lives in a repository

The repository is the heart of a Git-based project. It holds all the code plus the related files, such as:

  • A README file that describes the purpose of the project.
  • A license that states how other people may use the code.
  • Anything else the project needs.

A repository can be private (only people with accounts that have permission can see it) or public (searchable and visible to everyone).

Banking example: the code behind a payments service is private. A portfolio project I want employers to see is public.

The tabs in a new repository

A new repository opens on the Code tab. The others, in the order the video gives them:

  • Code: where all the source files live. Git started as a source code repository, though all sorts of files end up here now. At first only the README and license are here, if I created them.
  • Issues: track and plan work. It lists all open items against the project.
  • Pull Requests: part of how people collaborate. They show changes that are committed and ready for review before being merged into the main branch.
  • Projects: tools for managing, sorting and planning work. This is the core of GitHub's collaborative power.
  • Wiki, Security and Insights: often left for more advanced users. They give a communication base to the outside user community.
  • Settings: lots of personalisation, including renaming the repository and controlling who has access.

Real-life example: the tabs are like the sections of a project office. Code is the filing cabinet, Issues is the to-do board on the wall, Pull Requests is the approval tray, and Settings is the door lock.

Pseudocode: creating my first repository

``` sign in to GitHub click "New repository" type a repository name choose public or private tick "Add a README file" optionally add a license click "Create repository" open the Code tab and see the README ```

Tips for understanding the logic

  • Always add a README. It's the first thing anyone sees, and the evaluation briefs ask for one anyway.
  • Decide public or private before you push anything. Never put passwords or customer data in a public repository.
  • Pull Requests and Issues are where the teamwork happens. Code is only the storage.
  • If a tab looks unfamiliar, it's probably an advanced one (Wiki, Security, Insights), and it's fine to ignore it for now.

Recap

I can create and verify a free GitHub account. Repositories are storage structures that hold code, track issues and let me collaborate with others.
