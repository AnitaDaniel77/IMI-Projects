git-06: Module 1 Summary

What this lesson covers

The recap of Module 1, Getting Started with Git and GitHub. Everything in it is already in notes git-01 to git-05, so this page is the one-page revision sheet.

The key points

  • Git is a versatile version control system for tracking changes in code and collaborating on software projects.
  • Because Git is distributed, I can revert to a previous state or review the project's history from my own copy.
  • GitHub is one of the most popular web-hosted services for Git repositories.
  • A repository is a storage structure for documents, including application source code, that lets contributors track and maintain version control.
  • The Git repository model is mainly about tracking source code during development, and it has what's needed to coordinate programmers, track changes and support non-linear workflows.
  • Repositories hold code and track version history with Git. Platforms like GitHub add features on top, such as issue tracking and collaboration tools.
  • On GitHub I can create repositories, edit files in the web interface, commit changes, upload files, and more.

Real-life example: Git is the engine that records every change to a document, and GitHub is the office building around it, with meeting rooms (pull requests), a task board (issues) and keycard access (settings).

Pseudocode: Module 1 in one flow

``` create a GitHub account and verify the email create a repository with a README edit the README in the browser and commit add a new file and commit upload a file from my computer and commit ```

Quick self-test

  • Why is Git called distributed? (Every developer has a full copy of the history.)
  • What's the difference between Git and GitHub? (Git is the version control tool, GitHub hosts Git repositories online.)
  • What does a commit do? (Saves a snapshot of the changes with a message.)
  • What's in a repository besides code? (A README, a license and other project files.)

Tips for understanding the logic
