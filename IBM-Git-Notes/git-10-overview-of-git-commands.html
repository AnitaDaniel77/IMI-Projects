git-10: Overview of Git Commands

What this lesson covers

The basic commands for tracking and saving changes and sharing them with others, using the command line instead of the web interface. Two general command line commands (mkdir, cd) and eight Git commands (git init, git add, git commit, git log, git branch, git checkout, git merge, git status).

The scenario

A web developer wants to add a new HTML file to improve a web application. He wants to experiment with the code without disturbing the main code. The steps below follow him through it.

Real-life example: trying out a new layout for a shop window. You rearrange a mock-up in the back room, and the real window stays untouched until the owner approves it.

The commands, in the order they are used

  1. mkdir MyRepository: "make directory". Creates the project folder.
  2. cd MyRepository: moves me into that folder.
  3. git init: turns the folder into a Git repository. It sets up the files and data structure Git needs to manage version control.
  4. Create index.html with the content I need.
  5. git add: moves changes from the working directory to the staging area.
  6. git commit with the -m option: saves the staged snapshot to the project with a descriptive message, for example "created a new HTML file".
  7. git log: browse the commit history to confirm the commit was recorded.
  8. git branch code_list: lists, creates, renames or deletes branches. Here it creates a branch for experimenting in isolation.
  9. git checkout code_list: switches to an existing branch so I can develop there.
  10. Change index.html on the code_list branch, then git add and git commit again with a message like "updated index.html file in branch".
  11. git log on the branch: shows the new commit.
  12. git status: shows the state of my files in relation to the repository, such as what is changed, staged or untracked.
  13. git checkout main to go back to main, then git merge code_list to bring the branch's changes into main.

Real-life examples for each command

  • mkdir and cd: making a new folder in a filing cabinet and opening it.
  • git init: telling the office "start keeping a history of everything in this folder".
  • git add: putting papers in the outbox tray before filing them.
  • git commit: filing the tray with a note saying what's in it.
  • git log: reading the file's list of notes from oldest to newest.
  • git branch and git checkout: photocopying the file, then moving to work at the photocopy's desk.
  • git status: asking "what have I changed but not filed yet?"
  • git merge: stapling the approved changes from the copy into the original.

Pseudocode

``` make a folder and go into it initialize a git repository create index.html add index.html to the staging area commit with a message view the log to confirm the commit create a branch called code_list switch to code_list edit index.html add and commit the change view the log and the status switch back to main merge code_list into main ```

Tips for understanding the logic

  • The commands follow the same three places as before: working directory, staging area, repository. add moves from the first to the second, and commit moves from the second to the third.
  • Run git status often. It tells me exactly where I am and what to do next.
  • git branch only creates the branch. git checkout is what moves me onto it, so I always need both.
  • To merge, I stand on the branch I want to receive the changes (main), then name the branch to bring in (code_list).
  • git init in a folder inside another repository creates a nested repo, so I practise in a separate folder.
  • If git init creates a branch called master on my machine, the practice commands still work. I can rename it with git branch -M main.

Recap

mkdir creates a directory and cd moves into it. git init starts a repository, git add stages changes, git commit saves them, git log shows history, git branch creates a branch, git checkout switches branches, git merge brings branches together, and git status shows the state of my working directory.
