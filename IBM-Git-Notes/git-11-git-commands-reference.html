git-11: Git Commands Reference

What this reading covers

A reference of the Git commands I'll meet in real projects, with what each one does. The exact syntax for every command is in the cheat sheet file git-11-commands-cheatsheet.sh. I grouped them by job so they're easier to remember than one long alphabetical list.

1. One-time setup

  • git version shows which Git version is installed.
  • git config with global user.name and global user.email sets who I am. It must be done before the first commit, so my commits carry my name and email.
  • gh auth login logs me in to my GitHub account from the GitHub CLI, using a browser or a token, so I can manage repositories and pull requests from the terminal.

Real-life example: signing the visitor book at reception before you're allowed into the building.

2. Saving my work

  • git add puts changes in the staging area. It can take one file name, a dot for everything new or changed in the current folder, or -A for every change in the whole working tree wherever I'm standing.
  • git diff shows what changed: working directory against the last commit, the last two commits (HEAD~1 and HEAD), or two branches against each other.

Real-life example: git add is choosing which papers go in the envelope, and git diff is checking what's different from last week's copy before you seal it.

3. Branches

  • git branch lists branches, creates one when given a name, and deletes one with the -d option. To delete a branch, I first switch away from it with git checkout.
  • git checkout main switches to main.
  • git switch is the newer, simpler way to move between branches, and can also create a branch and move to it.

Real-life example: moving between desks in the same office. Each desk has its own pile of work, and the switch is walking over to the next one.

4. Working with remotes

  • git clone copies a remote repository to my machine, using its URL.
  • git pull fetches changes from the remote and merges them into my current branch. Switch to the branch I want updated first, then pull from origin.
  • git push uploads my local commits to the remote. Switch to the branch I want to push first, then push it to origin.
  • git remote lists the names of my remotes. With -v it also shows their URLs.
  • git remote add origin followed by a URL adds a remote called origin.
  • git remote rename changes a remote's name, for example from origin to upstream.
  • git remote rm removes a remote.

Real-life example: origin is the address of the shared drive. Pull is copying down what colleagues put there, and push is uploading mine.

5. Undoing things

  • git revert HEAD makes a new commit that undoes the last commit. History stays intact, so it's safe on shared branches.
  • git restore discards changes in a file by restoring it from the staging area or a commit. With the staged option it unstages a file. With the source option it restores from a specific commit.
  • git reset unstages changes. With the hard option and HEAD it throws away every uncommitted change in both the staging area and the working directory, and it can't be recovered.

Banking example: revert is a reversal entry on the ledger. The wrong entry stays visible and a new entry cancels it, so the audit trail is clean. Reset hard is tearing the page out, which is why it's dangerous.

6. Sharing work by email (older style, rarely used)

  • git format-patch creates patch files from commits, for example the last three, to share by email.
  • git request-pull generates a summary of pending changes, so the upstream maintainer knows what to review.
  • git send-email sends patch files as emails. The name and email must be configured first.
  • git am applies a patch file to my repository.

7. Specialist commands

  • git daemon serves repositories over the git:// protocol.
  • git instaweb launches a quick web server to browse a repository.
  • git rerere remembers how I resolved a merge conflict and reuses that fix next time, after setting rerere.enabled to true. It only applies to the same branch and commit conflicts.

Pseudocode: a normal day with these commands

``` switch to the branch I'm working on pull the latest changes from origin edit files check what changed (diff) stage the files (add) commit with a message push the branch to origin IF I committed something wrong: revert the commit IF I only changed a file and want it back: restore it ```

Tips for understanding the logic

  • Learn sections 1 to 5 first. Those are the daily commands, and the rest is occasional.
  • In the reading, the hard option appears as a long dash. In a real terminal it's two ordinary hyphens, written --hard, and the same for --global and --staged. A copy-pasted long dash won't work.
  • Before any reset --hard, commit or back up my work.
  • Pull before I push if others might have changed the branch.
  • Delete a branch only after it's merged, and only from a different branch.
  • When unsure, git status first, then decide.

Recap

Setup with config, save with add and commit, compare with diff, branch with branch, checkout and switch, share with clone, pull and push, manage remotes with the remote commands, and undo with revert, restore and reset.
