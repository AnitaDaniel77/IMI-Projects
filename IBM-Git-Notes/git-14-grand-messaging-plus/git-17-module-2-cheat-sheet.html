Git 17: Module 2 Cheat Sheet, Git Commands and Managing GitHub Projects

IBM Git and GitHub course, Module 2 reading. The official cheat sheet is alphabetical. These notes regroup it by what you are trying to do, with a few corrections where the sheet is thin.

1. Set up and inspect

CommandWhat it does
git --versionShows the Git version installed
git config --global user.name "Your Name"Sets the name on your commits
git config --global user.email "you@example.com"Sets the email on your commits
git init directoryCreates a new local repository in that directory
git clone repository-urlCopies a remote repository to your computer
git statusShows your working directory and the staged snapshot
git logBrowses previous changes; git log -p filename shows the changes to one file
git diff filenameCompares changes so others can review your work

Analogy: moving into a new office. You set your name badge, get a copy of the files, and look around to see what is on the desk.

2. Save your work

CommandWhat it does
git add sample.mdStages one file
git add .Stages all changed files in this folder and below
git commit -m "message"Saves the staged snapshot to the project history

Analogy: add is putting items in the box, commit is sealing and labelling it.

3. Branches and merging

CommandWhat it does
git branch new-branchCreates an isolated space to make changes
git checkout existing-branchSwitches to a branch
git checkout mainSwitches back to main
git merge feature_branchMerges that branch into the one you are on
git merge upstream/mainMerges the upstream project's main into your current branch

Analogy: a branch is a draft copy of the report. Merge is pasting the approved changes back into the final one.

4. Remotes and syncing

CommandWhat it does
git remote -vLists the remotes of this repo and their URLs
git remote add origin URLAdds a remote named origin
git remote add upstream URLAdds the original repository as upstream
git remote rename origin new-originRenames a remote
git fetch remote branchDownloads changes without merging them
git fetch upstream main:upstream-mainFetches upstream's main into a local branch named upstream-main
git pull origin mainFetches from origin and merges into your branch
git pull upstream mainPulls from the upstream repo into your branch
git pull downstream mainPulls main from a downstream repo, one that was forked from yours
git push origin your_branch_nameSends your committed changes to the remote

Tip: fetch looks, pull looks and merges. When in doubt, fetch first.

5. Undo

CommandWhat it does
git revert HEADUndoes the latest commit by adding a new commit that cancels it
git reset HEAD~1Moves the branch back one commit

Two corrections to the sheet. First, the sheet says reset undoes changes in the working directory. By default git reset keeps your files and only unstages the changes. Only git reset --hard throws the changes away, so treat that as destructive. Second, git revert HEAD opens an editor for the message. Adding --no-edit skips that.

Analogy: revert is a correction notice published in the next issue. Reset is pulling the page out of the printing run.

6. Sharing changes by email or patch

CommandWhat it does
git request-pullCreates a summary of pending changes for your upstream to pull
git format-patch -n number_of_commitsTurns commits into patch files for an email workflow
git send-email --to recipient patch-fileEmails one patch or a set of patches
git am < patchfile.patchApplies a patch that was emailed to you

The sheet's request-pull example is incomplete. The real form is git request-pull start-point repository-url end-point, for example git request-pull main https://github.com/you/repo.git feature-x.

Analogy: sending tracked changes by email instead of sharing the whole document.

7. Hosting and administration tools

CommandWhat it does
git daemon --reuseaddr --verboseLets others download from your repository anonymously
git http-backendServer-side Git over HTTP, supporting fetch and push
git instaweb -p 8080Starts a web front-end for your repositories on port 8080
git-shellA restricted login shell for users of a shared central repository
git rerereReuses a recorded resolution of a previous merge conflict

These matter mostly to the repository administrator role. The sheet's http-backend example actually shows how to prepare a bare repository (git clone --bare, then git update-server-info) so it can be served over HTTP.

Analogy: the building manager's toolkit. Opening the front door to visitors, installing a notice board, and keeping a note of fixes that worked before.

8. Pseudocode

```text set name and email once get the project: clone it, or init a new repo for every change: checkout a branch edit status, then add, then commit share it: fetch and merge to catch up push the branch open a pull request, or send a patch by email if something breaks: revert the bad commit (safe) reset only on your own local work (careful) ```
