Module 3: Java Collections Framework

What a collection is

A collection is just a group of objects. The Java Collections Framework (JCF) is the set of interfaces and classes Java gives you to store, retrieve, manipulate, and move around that group, instead of you having to manage a plain array by hand.

Real-life example: a shopping trolley. You don't care about a fixed number of slots, you just keep adding items, checking what's in there, and taking things out. The JCF is that trolley, built to actually fit how you work with groups of things.

List: ordered, duplicates allowed

A List keeps elements in the order you added them and lets the same value appear more than once. The two common implementations are ArrayList and LinkedList, and they trade off speed differently depending on what you're doing with the list.

ArrayList

Backed by a dynamic array. Fast when you're reading an element by its index (random access), slower when you're inserting or removing something from the middle, because everything after that point has to shift.

Real-life example: a numbered row of lockers. Jumping straight to locker 12 is instant, but squeezing a new locker into the middle of the row means physically renumbering everything after it.

list fruits = new ArrayList
fruits.add("Apple")
fruits.add("Banana")
fruits.add("Cherry")
print fruits                    // Apple, Banana, Cherry

firstFruit = fruits.get(0)      // grab by index, fast on an ArrayList
print firstFruit                // Apple

LinkedList

Backed by a doubly linked list, each element points to the one before and after it. Adding or removing elements is efficient since you're just relinking pointers, but reaching an element by index is slower because there's no direct jump, Java has to walk the chain.

Real-life example: a chain of people holding hands in a line. Cutting someone out or adding someone in is quick, you just re-grip hands either side of them, but finding the 7th person means walking down the line one by one.

list animals = new LinkedList
animals.add("Dog")
animals.add("Cat")
animals.add("Elephant")
print animals                   // Dog, Cat, Elephant

Set: unordered, no duplicates

A Set refuses duplicate values, adding the same element twice just gets ignored the second time. Two common implementations are HashSet and TreeSet.

  • HashSet: no guaranteed order, allows a null value.
  • TreeSet: keeps elements in sorted order, does not allow null.

Real-life example: a guest list at the door. Someone trying to check in twice just gets turned away the second time, they're already on the list, a Set behaves the same way with duplicate values.

set colors = new HashSet
colors.add("Red")
colors.add("Green")
colors.add("Blue")
colors.add("Red")               // ignored, Red is already in the set
print colors                    // Red, Green, Blue in some order

Map: unique keys to values

A Map pairs a key to a value, and every key has to be unique, adding a value under a key that already exists overwrites the old value rather than adding a second entry. Two common implementations are HashMap and TreeMap.

  • HashMap: allows null values, no guaranteed order.
  • TreeMap: allows null values, keeps keys in sorted order.

Real-life example: a phone's contact list. Each contact name is the key, their number is the value, you look someone up by name, not by scrolling through every number in order.

map ageMap = new HashMap
ageMap.put("Alice", 30)
ageMap.put("Bob", 25)
ageMap.put("Charlie", 35)
print ageMap                    // Alice=30, Bob=25, Charlie=35 in some order

aliceAge = ageMap.get("Alice")  // look up by key
print aliceAge                  // 30

Choosing between them

Logic: need order and duplicates allowed, reach for a List. Reading by index often, ArrayList. Adding/removing often, LinkedList. Need uniqueness with no particular order, HashSet, need it sorted, TreeSet. Need to look values up by a key instead of a position, that's a Map, HashMap if order doesn't matter, TreeMap if you want the keys sorted.
