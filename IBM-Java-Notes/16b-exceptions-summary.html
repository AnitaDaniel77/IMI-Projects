Basic exception handling

public class ExceptionExample {
    public static void main(String[] args) {
        int numerator = 10;
        int denominator = 0; // this will cause an ArithmeticException

        try {
            int result = numerator / denominator; // risky line
            System.out.println("Result: " + result);
        } catch (ArithmeticException e) {
            System.out.println("Error: Cannot divide by zero.");
        } finally {
            System.out.println("This block executes regardless of an exception.");
        }
    }
}

Real-life picture: try is attempting to withdraw cash, catch is the ATM telling you "insufficient funds" instead of swallowing your card, and finally is the screen resetting for the next customer either way.

Creating a custom exception

class MyCustomException extends Exception {
    public MyCustomException(String message) {
        super(message); // hand the message up to Exception
    }
}

public class CustomExceptionExample {
    public static void main(String[] args) {
        try {
            throw new MyCustomException("This is a custom exception message.");
        } catch (MyCustomException e) {
            System.out.println(e.getMessage());
        }
    }
}

Real-life picture: a generic "something went wrong" error is like a bank teller saying "computer says no". A custom exception is the teller saying exactly which rule failed, like "daily transfer limit exceeded".

How to read this code

  • Code that might fail goes in try. Keep it small so you know which line caused the trouble.
  • Each catch names the exception type it handles, so match it to what could actually go wrong.
  • finally is for cleanup only. No returns, no risky logic.
  • Custom exceptions extend Exception (checked) or RuntimeException (unchecked).
