Code Summary: Checked and Runtime Exceptions

Quick reference card for lesson 18.

Checked exception: FileNotFoundException

import java.io.File;
import java.io.FileNotFoundException;
import java.util.Scanner;

public class CheckedExceptionExample {
    public static void main(String[] args) {
        try {
            File myFile = new File("nonexistentfile.txt");
            Scanner myReader = new Scanner(myFile); // compiler forces us to handle this
            while (myReader.hasNextLine()) {
                String data = myReader.nextLine();
                System.out.println(data);
            }
            myReader.close();
        } catch (FileNotFoundException e) {
            System.out.println("An error occurred: " + e.getMessage());
        }
    }
}

Real-life picture: a statement file that hasn't arrived from head office. It isn't your code's fault, so you plan for it.

Runtime exception: ArithmeticException

public class RuntimeExceptionExample {
    public static void main(String[] args) {
        int numerator = 10;
        int denominator = 0;
        try {
            int result = numerator / denominator; // compiles fine, fails when it runs
            System.out.println("Result: " + result);
        } catch (ArithmeticException e) {
            System.out.println("An error occurred: Cannot divide by zero.");
        }
    }
}

Real-life picture: a teller dividing a payout by zero customers. That's a mistake in the logic, so the fix is in the code, not a bigger safety net.
