Module 4: Byte Streams

What a byte stream is

A byte stream reads or writes raw bytes, no interpretation, no encoding, just the data as-is. That makes it versatile enough to handle any file type, text, images, video, since it never tries to make sense of what the bytes mean.

Real-life example: a conveyor belt moving raw materials through a factory. The belt doesn't care whether it's carrying steel or plastic, it just moves whatever's on it, a byte stream moves whatever bytes are in the file the same way.

The core classes

InputStream and OutputStream are abstract classes, the superclasses every byte-reading or byte-writing class builds on. FileInputStream reads bytes straight from a file, FileOutputStream writes bytes straight to one. Wrapping either in BufferedInputStream or BufferedOutputStream adds buffering, which improves performance by reducing how often the program has to hit the disk directly.

Logic: InputStream/OutputStream are the blueprint, FileInputStream/FileOutputStream are the concrete file-based implementation, Buffered versions wrap those to make them faster.

Reading with FileInputStream

read() pulls one byte at a time from the file. When there's nothing left, it returns -1, that's the signal to stop. Each byte gets cast to a char before printing so it displays as text. The stream has to be closed afterward, typically in a finally block, so the resource gets released even if something goes wrong partway through.

import java.io.FileInputStream
import java.io.IOException

try:
    input = new FileInputStream("data.txt")
    byteValue = input.read()
    while byteValue != -1:
        print (char) byteValue
        byteValue = input.read()
catch IOException e:
    print "Error reading file: " + e.getMessage()
finally:
    input.close()                 // runs no matter what, even if an error occurred

Writing with FileOutputStream

write() sends either a single byte or a whole byte array to the file. Once the data's written, the stream gets closed, again typically inside a finally block, to make sure the resource is released properly.

import java.io.FileOutputStream
import java.io.IOException

try:
    output = new FileOutputStream("data.txt")
    output.write(byteValue)        // one byte
    output.write(byteArray)        // or a whole array of bytes at once
catch IOException e:
    print "Error writing file: " + e.getMessage()
finally:
    output.close()

Real-life example: copying a file byte by byte

Open the source file with FileInputStream and the destination with FileOutputStream, then loop, reading one byte and immediately writing it to the output, until read() returns -1. Close both streams when done.

input = new FileInputStream("source.txt")
output = new FileOutputStream("destination.txt")

byteValue = input.read()
while byteValue != -1:
    output.write(byteValue)
    byteValue = input.read()

input.close()
output.close()

Where byte streams get used

  • Reading and writing binary files, images, videos, anything that isn't plain text.
  • Network programming, sending and receiving binary data over sockets.
  • Serialization, converting an object into bytes for storage or transmission.
  • Multimedia applications, processing audio, video, or image data.

Byte streams vs character streams

Byte streamsCharacter streams
Base classesInputStream / OutputStreamReader / Writer
Common subclassesFileInputStream / FileOutputStreamFileReader / FileWriter
HandlesRaw bytes, no encodingCharacters, uses encoding
Best forBinary files, images, audioText files

Logic: if the file is meant to be read as human text, use a character stream, it handles the encoding for you. If the file is binary, or you genuinely don't care what the bytes represent, byte streams are the right tool, no encoding gets in the way.
