Module 4: Formatting Dates

What formatting a date means

A date object on its own isn't automatically readable to a person, formatting is converting that object into a string that follows a specific pattern. Java handles this through the DateTimeFormatter class, part of the java.time package introduced in Java 8 as the modern replacement for the older java.util.Date and java.util.Calendar classes.

Real-life example: a birthdate stored as 1990-05-15 means nothing warm to a user, formatted as "Tuesday, May 15th, 1990" it reads like something a person actually wrote. Same date, different purpose, raw for storage, formatted for display.

Common patterns

  • dd/MM/yyyy, day first, then month, then year.
  • yyyy/MM/dd, year first, then month, then day.
  • MM/dd/yyyy, month first, then day, then year.
  • EEEE, MMM d, yyyy, full weekday name, short month, day, full year.

Logic: which pattern to use depends on region and context, South Africa tends toward day-first, the US toward month-first, and a log file or database usually wants the unambiguous year-first order.

Formatting a LocalDate

The shape is always the same: import the classes, get the date, define a formatter with your pattern, call format() on the date passing that formatter, print the result.

import java.time.LocalDate
import java.time.format.DateTimeFormatter

today = LocalDate.now()
formatter = DateTimeFormatter.ofPattern("dd/MM/yyyy")
formatted = today.format(formatter)
print formatted                     // e.g. 02/10/2026

Where date formatting gets used

  • User interfaces, dates need to read naturally for whoever's looking at the screen.
  • Databases, many expect a specific date format to store values correctly.
  • Logging, a consistently formatted timestamp makes it possible to trace what happened when.

Real-life example: a registration system asking for a birthdate

Ask for a name and a birthdate, parse the birthdate string into a real LocalDate object, then format that object into something friendly to show back to the user.

Logic: parse() goes the opposite direction from format(), format() turns a date object into a string, parse() turns a string back into a date object, you need parse() first because the user typed plain text, not an actual LocalDate.

import java.time.LocalDate
import java.time.format.DateTimeFormatter
import java.util.Scanner

scanner = new Scanner(System.in)
print "Enter your name:"
name = scanner.nextLine()

print "Enter your birthdate (yyyy-MM-dd):"
input = scanner.nextLine()
birthdate = LocalDate.parse(input)        // turns the typed string into a real LocalDate

formatter = DateTimeFormatter.ofPattern("EEEE, MMM d, yyyy")
formatted = birthdate.format(formatter)

print "Hello " + name + ", your birthdate is " + formatted
scanner.close()

Typing John Doe and 1990-05-15 prints: "Hello John Doe, your birthdate is Tuesday, May 15th, 1990."

Which class to reach for

  • LocalDate: just the date.
  • LocalTime: just the time.
  • LocalDateTime: date and time together, no timezone.
  • ZonedDateTime: date, time, and timezone, for anything spanning regions.
