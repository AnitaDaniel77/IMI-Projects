Module 1: Constructors

What a constructor is

A constructor is a special method that runs automatically when an object is created, and sets up its initial state. It shares the class's exact name, has no return type at all (not even void), and is called automatically the moment you use new.

Real-life example: building a robot. Every part needs to be placed into position before it can actually function, the constructor is that assembly step, running once, before the object is ready to be used.

Logic: a constructor's only job is to get the object into a valid starting state, not to do ongoing work, that's what regular methods are for.

Default constructor

If you don't write any constructor at all, Java silently gives the class one for free, taking no parameters and setting attributes to Java's own defaults (0, null, false, etc, depending on the type).

class Dog:
    name
    // no constructor written, Java auto-generates one
    // Dog myDog = new Dog() still works, name defaults to null

No-arg constructor

This looks like the default constructor (no parameters) but is one you write yourself, so you control exactly what the default values are instead of relying on Java's blank defaults.

Important rule: the moment you write any constructor of your own, Java stops auto-generating the default one. So if you still want a no-argument option after adding a parameterized constructor, you have to write it explicitly.

class Car:
    model
    year

    // written by hand, not auto-generated, sets real default values
    function Car():
        model = "default model"
        year = 2020

Parameterized constructor

Accepts arguments so the object can be initialised with specific, meaningful values right at creation, instead of generic defaults.

Real-life example: instead of every Dog starting out as name = "unknown", `new Dog("Buddy")` gives that one dog its actual name immediately.

class Dog:
    name

    function Dog(dogName):
        name = dogName

// myDog = new Dog("Buddy")  -> name is "Buddy" right away

Constructor overloading

A class can have several constructors, as long as each has a different parameter list (different number or types of parameters). Java picks the right one to run based on what you pass to new.

Logic: think of it like ordering coffee, "give me a coffee", "give me a coffee with milk", "give me a coffee with milk and sugar" are all valid requests, each maps to a different constructor depending on how much detail you give.

Why use constructors, and best practices

  • They guarantee an object is properly initialised before anything else touches it.
  • Parameterized constructors let the same class be created in different valid starting states.
  • Keeping initialisation logic in the constructor (rather than scattered across setter calls after creation) makes the code easier to read and maintain.

Keep constructors simple, focused only on initialisation, not complex logic or calculations. Prefer parameterized constructors when the object genuinely needs meaningful starting values. Avoid overloading with too many near-identical constructors just for the sake of it, it gets confusing fast.
