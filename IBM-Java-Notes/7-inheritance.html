Module 2: Inheritance

What inheritance is

Inheritance lets one class, the subclass (child), derive properties and methods from another class, the superclass (parent), using the extends keyword. It promotes code reuse, you don't rewrite what the parent already has, and lets you structure related classes into a hierarchy.

Real-life example: a smartphone inherits basic functions like calling and texting from a plain Phone, but adds its own features on top, sensors, apps, a touchscreen, rather than being built from scratch.

Logic: a subclass automatically gets every public and protected member of its superclass, it only needs to define what's new or different, not the whole thing over again.

Key terms

  • Superclass: the class being inherited from.
  • Subclass: the class doing the inheriting.
  • extends: the keyword that sets up the relationship.

A subclass inherits all public and protected members from its superclass, but not private ones, those stay locked to the superclass itself.

class Animal:
    name

    function eat():
        print name + " is eating"

class Dog extends Animal:
    function bark():
        print name + " is barking"

// Dog inherits eat() automatically, and adds its own bark()
myDog = new Dog()
myDog.name = "Buddy"
myDog.eat()   // inherited
myDog.bark()  // Dog's own

Types of inheritance

  • Single: one class inherits from exactly one superclass. Dog extends Animal.
  • Multilevel: a chain, a subclass inherits from a subclass. Puppy extends Dog, and Dog extends Animal, so Puppy gets everything from both.
  • Hierarchical: several subclasses share the same superclass. Dog and Cat both extend Animal independently.
  • Multiple: one class inheriting from more than one superclass directly. Java doesn't allow this for classes (it would be ambiguous if two parents defined the same method differently), but the same effect is achieved through interfaces instead.

Real-life example: multilevel is like a family tree, a grandchild inherits traits passed down through a parent, not directly from the grandparent. Hierarchical is like siblings, Dog and Cat are different, but both are still built on the same Animal foundation.

Method overriding

A subclass can redefine a method it inherited, giving it its own version instead of using the parent's. Java calls whichever version actually belongs to the real object's type, even if the variable is declared as the parent type.

Real-life example: Animal's sound() might print a generic "Animal makes a sound", but Dog overrides it to print "Dog barks" instead. Even if you write `Animal myDog = new Dog()`, calling sound() still runs Dog's version, because that's what myDog actually is underneath.

Logic: the declared type of the variable decides what you're allowed to call, the actual type of the object decides which version of that method actually runs.

class Animal:
    function sound():
        print "Animal makes a sound"

class Dog extends Animal:
    function sound():          // overrides the parent's version
        print "Dog barks"

myDog = new Dog()  // even if declared as Animal, sound() still runs Dog's version

Where this shows up in real systems

  • Game development: characters share common properties (health, position) from a base Character class, but each subclass has its own unique abilities.
  • UI components: buttons, text boxes, and labels can all inherit shared behaviour from a base component class, while implementing their own specific actions.
  • Data models: keeps consistency across related entities while still letting each one have its own unique fields.
