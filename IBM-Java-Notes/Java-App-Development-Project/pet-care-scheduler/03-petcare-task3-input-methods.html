PetCare Scheduler: Task 3, The Input Handling Methods

Lab step 1: registerPet()

Collects the pet's details and adds the pet to the HashMap. The ID is checked first with containsKey(), so a duplicate stops the whole registration before anything else is asked. Name, species, owner and contact use a small helper that keeps asking until the answer isn't empty. Age loops until it is a whole number of 0 or more. The registration date is never typed, because the Pet constructor sets it with LocalDate.now(), so there is no date input to get wrong.

Integer.parseInt throws NumberFormatException for text like "abc". That is a kind of IllegalArgumentException, so catching IllegalArgumentException covers both the text case and the negative case in one place.

Real-life example: a vet's reception form. The receptionist won't accept a blank name, and won't accept "-3 years" for an age.

registerPet():
    id = ask until not empty
    if id already in pets: print error, stop
    name, species = ask until not empty
    repeat:
        read age as a whole number
        if not a number or negative: print error and ask again
    owner, contact = ask until not empty
    pet = new Pet(...)
    pets.put(id, pet)
    print "registered on" + pet's registration date

Lab step 2: scheduleAppointment()

Three validations, in the order the lab lists them. First, the pet ID must exist, otherwise the method stops. Second, the type must be one of vet visit, vaccination or grooming. The input is lowercased and trimmed, then checked against a fixed list, so "Vet Visit" still works. Third, the date and time must parse in the format yyyy-MM-dd HH:mm and must be after now.

The formatter uses STRICT mode with the pattern letter u. In normal mode Java quietly turns 30 February into 28 February. In strict mode it rejects it as invalid, which is what we want from user input. Notes are optional, so pressing Enter leaves them empty.

Real-life example: booking at a clinic. They check the pet is on file, that you picked a service they offer, and that the slot isn't in the past.

scheduleAppointment():
    id = ask
    pet = pets.get(id)
    if pet is missing: print error, stop
    repeat: ask for type, lowercase it, until it is in the allowed list
    repeat:
        ask for date and time
        try to parse with strict yyyy-MM-dd HH:mm
        if parse fails: print format hint
        else if not after now: print "must be in the future"
        else: stop repeating
    notes = ask (can be empty)
    pet.addAppointment(new Appointment(type, dateTime, notes))
    print confirmation

Lab step 3: saveData()

Writes the whole pets map to pets.ser with an ObjectOutputStream. Because every Pet holds its own appointments and everything is Serializable, one writeObject call saves all pets and all appointments together. try-with-resources closes the file automatically. It returns true or false so main can tell whether the save worked.

Real-life example: photocopying the entire filing cabinet in one go and keeping the copy somewhere safe.

saveData():
    try open "pets.ser" for writing
        write the pets map
        print "Data saved."
        return true
    catch problem writing:
        print error
        return false

Lab step 4: the display methods

All four methods read from the same data and differ in what they filter. HashMap has no useful order, so a helper sorts pets by ID and another sorts a pet's appointments by date, which keeps the output steady between runs.

displayPets() prints every pet. displayPetAppointments() asks for an ID and prints that pet's appointments in date order. displayUpcomingAppointments() prints appointments after now for every pet. displayAppointmentHistory() prints appointments before now for every pet, with a "none" line when a pet has no history.

Real-life example: the same diary viewed three ways: everything for one pet, everything still to come, and everything already done.

upcoming: for each pet, for each appointment:
    if appointment time is after now: print it

history: for each pet:
    print pet heading
    for each appointment:
        if appointment time is before now: print it
    if none printed: print "No past appointments."

Lab step 5: generateReports()

Two reports. The first lists appointments between now and seven days from now. The second finds pets overdue for a vet visit: for each pet it looks through the past "vet visit" appointments, keeps the most recent one, and flags the pet if there is none, or if it is older than six months (now minus 6 months). A newly registered pet with no visit yet shows up as overdue, which matches the lab's example of "no vet visit in the last 6 months".

Real-life example: the clinic's morning checklist: who is coming in this week, and who we should phone because they haven't been in for ages.

generateReports():
    now = current date and time
    nextWeek = now + 7 days
    sixMonthsAgo = now - 6 months

    report 1: for each pet, for each appointment:
        if time is after now and not after nextWeek: print it

    report 2: for each pet:
        lastVisit = nothing
        for each appointment that is a "vet visit" and in the past:
            keep the latest time as lastVisit
        if lastVisit is nothing or before sixMonthsAgo:
            print the pet as overdue

Lab step 6: the switch in main()

Each case calls one method. Case 8 saves. Case 9 saves and only exits if the save worked.

Tips for reading this logic

  • Every handler has the same shape: ask, validate, act, confirm. Find those four parts in each method.
  • A while(true) loop with a break is the "keep asking until valid" pattern. The break is the only way out.
  • For the date checks, picture a timeline with now in the middle: before now is history, after now is upcoming.
