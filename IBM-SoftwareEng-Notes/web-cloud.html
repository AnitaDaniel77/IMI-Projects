Overview of Web and Cloud Development

How a website actually gets to you

You open a browser (Chrome, Edge, Firefox, Safari), type a URL into the address bar, and the browser contacts that server, asking for the site's content. The server sends back a response — typically three things:

  • HTML — the structure of the page (plain, unstyled)
  • CSS — the styling and visual presentation
  • JavaScript — interactivity and dynamic behavior

Static vs dynamic content

Static content is already stored on the server and sent as-is. Dynamic content gets generated fresh each time it's requested, often pulling in data from other systems like a database. Most real websites blend both — some content is pre-built, some is assembled on the fly per user or per request.

Real banking example

The Capitec app's marketing page ("Open an account") is largely static — same content for everyone. Your actual account dashboard showing your balance and recent transactions is dynamic — it's generated fresh each time you log in, pulling live data from Capitec's backend systems specifically for your account.

Cloud applications

Work the same basic way as websites (client requests, server responds), but are built to run on cloud infrastructure — cloud-based backend, cloud data storage/processing, and other cloud services. This is what gives them strong scalability (handling more users without a full infrastructure rebuild) and resilience (staying up even if part of the system has issues).

Front-end vs back-end vs full-stack

  • Front-end — everything on the client side, what the user actually sees and interacts with. Built with HTML, CSS, JavaScript, and related frameworks/libraries/tools.
  • Back-end — everything happening on the server before data reaches the client. Handles logic, functionality, and authentication/security. Back-end developers often work with relational or NoSQL databases, sometimes alongside dedicated database administrators on larger projects.
  • Full-stack — skills and experience spanning both front-end and back-end.

Tools of the trade

A code editor is usually the first tool developers pick up. An IDE (Integrated Development Environment) goes further — bundling code editing with build, compile, and debug capabilities. Good IDEs support multiple languages and integrate with version control tools like Git and GitHub, plus offer extensions/themes for customizing your workflow. Examples: Sublime Text, Atom, Vim, VS Code, Visual Studio, Eclipse, NetBeans.

Logic to hold onto

The client-server request/response cycle is the foundation everything else in web development sits on top of. Once you genuinely understand "browser asks, server answers, response contains HTML/CSS/JS," every more advanced topic — APIs, databases, cloud infrastructure — is really just adding detail to one side or the other of that same basic exchange.
