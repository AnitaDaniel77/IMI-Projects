What Does a Software Engineer Do?

The core skillset

Software engineers combine engineering, mathematics, and computing to design and build software that solves real-world problems. It's naturally suited to analytical thinkers who enjoy problem-solving.

What they build

A wide range: desktop and web applications, mobile apps, games, operating systems, network controllers. Built using programming languages, development environments, frameworks/libraries, databases, and servers.

Two categories of software engineer

  • Back-end engineers (system developers) — build the computer systems and networks that front-end applications rely on.
  • Front-end engineers (application developers) — client-focused; build what users actually interact with, including Android, iOS, Windows apps, and platform-agnostic websites.

Where software engineers work

Teams typically build one of three types of software:

  • Off-the-shelf software (sold broadly to many customers)
  • Bespoke software (built to a specific client's requirements)
  • Internal software (for people within your own organization)

Within a team, you might specifically work on:

  • Data integration layers — accessing and loading data from various sources into the solution.
  • Business logic — applying real-world business rules to that data.
  • User interfaces — enabling users to actually interact with the solution.

Real banking example

Your own IMI programme is training you as a back-end engineer specifically — building the systems (Java, Spring, databases) that Capitec's front-end apps and websites rely on. The "internal software" category is also directly relevant: a lot of what banks build isn't customer-facing at all — internal tools for staff, risk assessment systems, compliance dashboards — all still real software engineering work, just never seen by the public.

Day-to-day tasks

  • Taking user specifications and designing new systems to meet them
  • Writing code and testing it works as expected
  • Evaluating and testing new software programs
  • Optimizing software for maximum efficiency
  • Maintaining and updating existing systems
  • Documenting code so other developers can understand it
  • Presenting new systems to users and customers

Some engineers, particularly DevOps practitioners, also handle integrating and deploying code onto infrastructure. Beyond building your own systems, you'll also regularly be testing, improving, and maintaining software your colleagues built.

How responsibilities grow over a career

Junior roles typically focus on a narrower set of responsibilities: writing, testing, deploying, and documenting code. As a career progresses, responsibility widens — a senior engineer typically owns multiple areas of a software solution, including planning and design phases, not just implementation.

Real banking example

This tracks exactly with your own IMI Java Trainee trajectory — right now the focus is heavily on writing and testing code (your capstones, your Udemy practice), but the programme's later modules (Design Patterns, the capstone projects with more architectural scope) are deliberately building you toward the wider planning/design responsibility a more senior engineer eventually holds.

Logic to hold onto

The front-end/back-end split and the junior/senior responsibility growth are really the same underlying idea at different scales: engineers start narrow and specific (one layer, one small piece of code) and grow toward broader ownership (multiple layers, multiple areas, eventually the design decisions themselves). Recognizing which "layer" of responsibility you're currently building experience in — and which one you're aiming toward — is a useful way to track your own growth deliberately rather than just accumulating tasks.
