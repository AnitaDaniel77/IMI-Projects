What Is Software Engineering?

Definition

Software engineering is the application of scientific, systematic principles to designing, building, and testing software so it satisfies actual business requirements — not just "writing code that runs," but writing code shaped by a structured process that collects and analyzes what the business actually needs first.

Real banking example

At Capitec, when the IMI Java team builds something like a new loan-approval module, engineering doesn't start with typing Java. It starts with gathering requirements from the business side (risk team, compliance, product owners), analyzing what the system actually needs to do, then designing an architecture before a single class gets written. Skipping straight to code without that step is exactly the kind of "ad hoc programming" this lesson says caused the software crisis.

A short history: the software crisis

From the mid-1960s to mid-1980s, software development had no formal process. As computers spread everywhere, demand for complex software outpaced the industry's ability to build it reliably. Projects ran over budget, missed deadlines, and shipped as unmanageable, buggy code. Solutions built for small systems often couldn't scale to large, complex ones — and by the time a project finally shipped, the technology it was built on was already outdated, forcing teams to redesign from scratch.

The fix was turning unstructured coding efforts into a real engineering discipline, backed by the rise of CASE tools (Computer-Aided Software Engineering) in the mid-1980s, split into six categories: business analysis and modeling, development tools (like debuggers), verification and validation tools, configuration management, metrics and measurement, and project management.

Real banking example

Banking software specifically cannot afford "software crisis" behavior — a buggy release in a payments system isn't just inconvenient, it's a compliance and financial risk. This is part of why Capitec's IMI programme pushes structured practices this early: version control, capstones, documented processes, and formal review cycles all exist to prevent exactly the chaos this lesson describes.

Software Engineer vs Software Developer

The terms get used interchangeably, but there's a scope difference:

  • Software Engineer — broader knowledge, systematic big-picture thinking, builds entire systems, usually on larger-scale projects, focused on overall structure rather than one immediate problem.
  • Software Developer — narrower scope, more creative/problem-focused approach, writes code to implement specific functionality within a system someone else may have architected.

Real banking example

A developer on your team might be the one writing the specific function that validates an account number format. A software engineer is the one who decided how the whole account-validation *system* fits together — which services call it, how errors propagate, how it scales when Capitec onboards another million customers.

Responsibilities of a Software Engineer

  • Designing, building, and maintaining software systems
  • Writing and testing code
  • Consulting with stakeholders — clients, third-party vendors, security specialists, and other team members

Logic to hold onto

Engineering isn't defined by the code itself, it's defined by the process wrapped around the code: gather requirements, design, build, test, maintain, repeat. That process is formalized as the Software Development Lifecycle (SDLC), which is the next topic in this module.
