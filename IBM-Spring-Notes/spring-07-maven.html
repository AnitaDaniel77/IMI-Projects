Spring 07: Maven

What Maven is

Maven is a build and project management tool for Java. It downloads the libraries you need, compiles your code, runs the tests and packages the result into a JAR. You describe the project once in a file called pom.xml and Maven does the rest.

Real-life example: Maven is a recipe card plus a shopping service. The pom.xml lists the ingredients (dependencies) and the steps (lifecycle), and Maven fetches the ingredients from the shop (Maven Central) and cooks in the right order.

The five key parts

  • POM (pom.xml): the project's configuration and the heart of every Maven project.
  • Dependencies: external libraries declared in the POM and downloaded automatically.
  • Repositories: where libraries are stored. Maven Central is the default, others can be added.
  • Build lifecycle: validate, compile, test, package, verify, install, deploy.
  • Plugins: add abilities such as compiling, packaging or generating docs.

Real-life example: the lifecycle is a production line. A phase only runs after every phase before it has passed, so running mvn install also validates, compiles, tests and packages first.

Inside pom.xml

  • project: the root element, defines the XML namespace.
  • modelVersion: the POM format version, almost always 4.0.0.
  • groupId: your organisation, written like a domain (com.example).
  • artifactId: the unique name of the project (spring-demo).
  • version: the edition. SNAPSHOT at the end means still in development.
  • packaging: jar by default, or war.
  • dependencies: each one has groupId, artifactId, version and scope.
  • build: plugins and their goals.
  • repositories: extra places to look for libraries.
  • properties: your own variables, for example the project-wide Java version.
  • profiles: different setups for development and production, switched on from the command line.

Real-life example: groupId, artifactId and version together are the project's address, like street, house number and flat number. Maven uses them to find exactly one library.

Maven in IntelliJ

New Project, choose Maven, fill in groupId and artifactId. Type "dependency" in pom.xml and autocomplete gives you the tag. The Maven tool window lets you double-click clean, compile or install. In VS Code the same goals run from the terminal.

Tips to understand it

  • Read a pom.xml top to bottom as three questions: who am I (group, artifact, version), what do I need (dependencies), how am I built (build and plugins).
  • If a class is "not found", check the dependency first. If the build fails, check which lifecycle phase it stopped at.
  • Phases run in order, so you never need to run compile before test yourself.

Pseudocode

``` READ pom.xml FOR each dependency listed IF not in local repository download from Maven Central RUN lifecycle phases up to the one requested validate -> compile -> test -> package -> verify -> install -> deploy STOP at the first phase that fails RESULT: a JAR in the target folder ```
