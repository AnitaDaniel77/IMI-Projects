Spring 08: Defining a Spring Project

The idea

Defining a Spring project means setting up the tools, creating a Maven project, adding the Spring libraries as dependencies, and writing a first configuration class, bean and main class.

Real-life example: you are the head chef writing the order. You list the ingredients (dependencies) and Spring, the kitchen, prepares the dish (the application) from that list.

Step 1: Set up the environment

Install a JDK (Oracle or OpenJDK) and Maven, then check both with java -version and mvn -version. Each must print version details.

Real-life example: checking the oven and the pans work before you start cooking.

Step 2: Create the Maven project

Either use the command line (set the groupId and artifactId) or an IDE wizard and choose Maven. The groupId is the unique organisation name, the artifactId is the project name.

Step 3: Know the standard structure

  • pom.xml at the root: project details, dependencies, build setup.
  • src/main/java: the application code (configuration classes, services, controllers).
  • src/main/resources: config files, HTML, CSS, templates.
  • src/test/java: unit and integration tests, for example with JUnit.
  • src/test/resources: files only the tests need, like mock data.

Real-life example: a kitchen with labelled shelves. Everyone knows where the ingredients, the tools and the taste-test spoons live, so a new colleague finds things at once.

Step 4: Add dependencies

Add the Spring library to pom.xml (here spring-context, which holds the IoC container). Maven downloads it and everything it needs. The lesson runs mvn clean install for this.

Step 5: Write the first Spring app

  • HelloBean: a plain class with one method that prints a message.
  • AppConfig: a class marked @Configuration with a @Bean method that creates the HelloBean.
  • MainApp: starts the Spring container, asks it for the bean and calls the method.

Real-life example: AppConfig is the menu, HelloBean is the dish, and MainApp is the waiter who asks the kitchen (the container) for it instead of cooking it himself.

Step 6: Compile and run

Build with Maven or run MainApp from the IDE. The console prints the message, which proves Spring created and managed the bean.

Tips to understand the logic

  • Notice that MainApp never writes new HelloBean(). Spring creates it, MainApp only asks for it. That is the whole point of IoC.
  • Read it as three questions: what is the bean (HelloBean), who creates it (AppConfig), who uses it (MainApp).
  • If getBean fails, check that the @Bean method exists and that AppConfig was passed to the container.

Pseudocode

``` CHECK java and mvn are installed CREATE maven project (groupId com.example, artifactId spring-project) ADD spring-context dependency to pom.xml DOWNLOAD dependencies with maven DEFINE HelloBean with method sayHello() PRINT "Hello World from Spring" DEFINE AppConfig (@Configuration) @Bean method returns a new HelloBean MAIN START Spring container using AppConfig GET HelloBean from the container CALL sayHello() CLOSE container ```
