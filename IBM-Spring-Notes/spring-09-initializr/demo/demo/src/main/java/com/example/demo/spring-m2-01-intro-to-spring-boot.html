Spring Boot in one sentence

Spring Boot is the Spring Framework with the setup already done for you, so you spend your time writing the business code.

Real-life example: opening a coffee shop. Spring Framework is sourcing suppliers, designing the menu and hiring staff yourself. Spring Boot is a franchise where the kitchen, menu and suppliers arrive ready. In my project, the fraud engine has no server setup and no database wiring, only rules.

Key features

  • Auto-configuration: sets things up based on the libraries in the project
  • Standalone applications: the web server is inside the app, so it runs by itself
  • Production-ready features: built-in health and monitoring tools
  • Spring Boot CLI (Command Line Interface, typing commands in a terminal): quick prototypes with Groovy scripts
  • Spring Initializr: a website that generates a starter project with the dependencies you choose

The four core concepts

1. Auto-configuration

Spring Boot looks at the libraries in the pom.xml and creates the objects (beans) those libraries need.

Real-life example: I add the H2 database library and Spring Boot sets up the database connection without me writing any connection code. In my fraud engine, that is why there is no database class at all, only repositories.

2. Embedded server

A web server (Tomcat or Jetty) is packaged inside the application, so there is nothing to install or configure outside.

Real-life example: a portable kitchen. Everything is in the van, so it works wherever you park. My fraud engine started on port 8080 from one command, and the same jar went into a Docker container unchanged.

3. Actuator

Built-in endpoints that report the application's health and metrics.

Real-life example: the dashboard in a car showing fuel and engine temperature. My fraud engine answers at /actuator/health with status UP, and my CI robot used that to check the container had started.

4. Externalized configuration

Settings live in application.properties or a YAML file (YAML stands for YAML Ain't Markup Language, a simple indented settings format), outside the code.

Real-life example: playlists for different moods. The songs (code) stay the same, and you switch the playlist (settings) per environment. In my project the high-amount limit of 10000 sits in application.properties, so the bank can change it without a programmer.

Spring Framework or Spring Boot?

Choose Spring Framework when

  • The enterprise application is complex and needs detailed control of configuration, security and transactions
  • You are working with a legacy system already built on Spring
  • You have custom infrastructure needs (specific servers, custom transaction setup)
  • You are migrating an old application gradually instead of rewriting it

Choose Spring Boot when

  • You want rapid development with minimal setup
  • You are building microservices (small independent services)
  • You are prototyping or building an MVP (Minimum Viable Product, the smallest version that proves the idea)
  • The target is cloud or containers
  • You are starting a new project from scratch

Real-life example: Capitec adding a small new service next to old core banking could use Boot. Changing a large, long-running Spring system with custom rules is more likely Framework work.

Pseudocode: what happens when a Boot app starts

``` START the application (main method) READ the libraries listed in pom.xml FOR each library found CREATE the default beans that library needs // auto-configuration READ application.properties // externalized configuration START the embedded web server on port 8080 // embedded server PUBLISH /actuator/health // actuator WAIT for requests ```

Tips to understand it

  • Boot does not replace Spring, it sits on top of it. Everything Boot does, Spring can do manually.
  • Ask one question per concept: what did I not have to write? (auto-configuration: bean setup, embedded server: server setup, externalized configuration: hard-coded values)
  • Memory trick: Auto, Embedded, Actuator, External. The first letters spell AEAE, so think "Always Easier, Always Easy".

Summary

  • Boot automates configuration and embeds the server, which cuts setup time
  • Four core concepts: auto-configuration, embedded server, actuator, externalized configuration
  • Framework for control and legacy, Boot for speed, microservices, MVPs, cloud and new projects
