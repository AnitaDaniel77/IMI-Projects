Authentication and Authorization in Spring

The difference

Authentication checks who you are. Authorization checks what you're allowed to do once you're in.

Real-life example: at a high-security building, the iris scan confirms it's you (authentication). Then the system checks which rooms your badge opens (authorization).

Acronyms in this lesson

  • JAR: Java ARchive, one packaged file that holds the whole app.
  • pom.xml: POM stands for Project Object Model. It's the Maven file that lists your dependencies.
  • URL: Uniform Resource Locator, a web address like /admin/dashboard.
  • RBAC: Role-Based Access Control, permissions grouped under roles.

Step 1: Create the project

On Spring Initializr choose Maven, Java, the latest stable Spring Boot, JAR packaging and your Java version. Add Spring Web and Spring Security, generate, unzip and open it in your IDE.

If you forgot Spring Security, add the spring-boot-starter-security dependency to pom.xml later.

Real-life example: as soon as Spring Security is added, every page gets locked by default, like a new branch where all doors start locked until you decide which ones open.

Step 2: The security config class

  • @Configuration: this class sets things up for Spring.
  • @EnableWebSecurity: switches on web security.

Step 3: In-memory users

User details are kept in the app's memory instead of a database. Two users are created:

  • user / password with role USER
  • admin / adminpass with role ADMIN

Good for testing only. Everything is lost when the app stops, and real apps load users from a database.

Real-life example: a guest list written on a whiteboard at the door. Quick for a small event, but it gets wiped at the end of the day.

Step 4: URL rules

  • /public/** is open to everyone.
  • /user/** needs the USER role.
  • /admin/** needs the ADMIN role.
  • formLogin() means anyone hitting a protected page gets sent to a login form first.

Real-life example: the banking hall is public, the consultant desks are staff only, and the server room is IT only.

Authorization concepts

  • Roles: broad labels like USER or ADMIN that decide what someone can do.
  • Authorities: specific actions, like READ_ACCOUNT or EDIT_ACCOUNT. A role is really a group of authorities.
  • RBAC: access is given based on the role you hold.
  • Method-level security: @PreAuthorize on a method adds a second check after the URL rule.

Real-life example: "Service Consultant" is a role. "Can reverse a transaction" is an authority that role may or may not include.

Step 5: The controller

  • /public/hello: no annotation, anyone can see it.
  • /user/profile: @PreAuthorize("hasRole('USER')").
  • /admin/dashboard: @PreAuthorize("hasRole('ADMIN')").

Pseudocode


SETUP
    create user "user" with role USER
    create user "admin" with role ADMIN
    rule: /public/** open to all
    rule: /user/** needs USER
    rule: /admin/** needs ADMIN
    turn on login form

WHEN request comes in
    IF path is public
        show page
    ELSE IF not logged in
        show login form
        check username and password
    IF logged in
        IF role matches URL rule AND method rule
            show page
        ELSE
            return 403 Forbidden

Tips for understanding the logic

  • Ask two questions for every endpoint: who are you, and are you allowed here?
  • hasRole("ADMIN") looks for the authority "ROLE_ADMIN". Spring adds ROLE_ for you.
  • URL rules and @PreAuthorize can both apply. The request has to pass both.
  • @PreAuthorize only works if method security is switched on with @EnableMethodSecurity.

Testing

Run the app, open /public/hello without logging in, then try /user/profile and /admin/dashboard with each user. The "user" account should get 403 on the admin page.
