File Upload with Spring MVC and Spring Boot

What this lesson covers

How to let a user pick a file in the browser, send it to the server, save it in a folder, and show a status message. MVC stands for Model-View-Controller. JDK is the Java Development Kit (the tools to write and run Java). IDE is an Integrated Development Environment, like VS Code or IntelliJ.

Example: a client uploads a payslip or ID copy when applying for a loan online.

Prerequisites

  • JDK 17 or later, because Spring Boot 3 needs it.
  • A Spring Boot project made with Spring Initializr.
  • An IDE for writing and running the code.

Step 1: Dependencies

  • Spring Web: controllers and HTTP (HyperText Transfer Protocol, how the browser and server talk).
  • Thymeleaf: HTML templates the server fills with data.
  • Spring Boot DevTools: restarts the app automatically when you save changes.

Real-life example: DevTools is like a printer that reprints the form every time you correct it, so you don't have to walk back and press print.

Step 2: Set size limits in application.properties

Two settings control uploads:

  • max-file-size: the biggest single file allowed.
  • max-request-size: the biggest total for one request, which matters if several files are sent together.

Multipart means the request is split into parts, so a file can travel with normal form fields.

Real-life example: a branch scanner that only accepts documents up to a certain number of pages. Anything bigger gets rejected at the door.

Step 3: The controller

  • GET / shows the upload page.
  • POST /upload receives the file as a MultipartFile using @RequestParam("file"). The name must match the input's name attribute in the form.
  • If the file is empty, add a message and redirect to the status page.
  • Otherwise read the bytes, build a path inside the uploads folder, write the file, and add a success message.
  • GET /uploadStatus shows the status page.

RedirectAttributes with addFlashAttribute keeps the message alive for one redirect only, then it disappears.

Real-life example: a flash attribute is like a sticky note the teller hands you to take to the next counter. Once that counter reads it, it gets thrown away.

Note: the uploads folder must exist or the write fails. My code creates it if it's missing.

Step 4: Thymeleaf templates

  • upload.html: a form with method POST and enctype multipart/form-data, a file input named "file", and a submit button.
  • uploadStatus.html: shows the message with th:text and links back to the upload page.

Without enctype multipart/form-data, the browser only sends the file name, not the file itself.

Real-life example: enctype is like choosing "parcel" instead of "letter" at the post office. Pick letter and only the address goes through.

Pseudocode: upload flow


WHEN user opens /
    show upload page

WHEN user submits a file to /upload
    IF file is empty
        save message "Please select a file"
        redirect to /uploadStatus
    TRY
        make sure uploads folder exists
        read file bytes
        build path = uploads folder + original file name
        write bytes to path
        save message "Uploaded successfully"
    CATCH error
        save message "Upload failed"
    redirect to /uploadStatus

WHEN /uploadStatus loads
    show the saved message

Tips for understanding the logic

  • Match names across files: the input name="file" must match @RequestParam("file").
  • "redirect:/uploadStatus" sends the browser to a new URL. A plain "uploadStatus" just shows the template without changing the URL.
  • Redirecting after a POST stops the file uploading twice if the user refreshes the page.
  • Follow the try/catch: anything that touches the disk can fail, so it sits inside try.

Running it

Run from the IDE or with mvn spring-boot:run (mvn is Maven, the build tool), then go to http://localhost:8080/.
