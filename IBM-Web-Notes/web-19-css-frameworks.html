What a CSS framework is

A framework is a foundation to build your code on. A CSS framework gives you the tools to put together a basic user interface quickly: navigation bars, forms, grids and other visual elements, and pages that adjust to any screen size. Frameworks have to be chosen at the start of a project, so it helps to know the types before you begin, and to decide which features matter most for the project.

Utility-first and Tailwind CSS

Instead of writing text-align: center in a style rule, a utility class such as text-center does the same job when placed in the class attribute. Tailwind CSS is the popular example. Its classes are composed together right in the markup.

Take a dangerous link, such as "Report fraud": underlined, red, and a darker red when hovered. In vanilla CSS you write one rule for the normal state and another for the hover state. In Tailwind you list the classes on the link itself.

The hover part is a modifier, a prefix that makes a class apply only in a certain situation. The md modifier applies a class only when the screen is wider than 768 pixels (Tailwind's medium screen). An image can be 64 pixels wide by default, 128 on medium screens and 192 on large screens, with all three sizes set in the one element. Modifiers like these make responsive pages quick to build.

Component frameworks and Bootstrap

Bootstrap is the popular component framework, described in the lecture as a feature-packed front-end toolkit for building fast, responsive sites. The same danger link is just one class, link-danger. Bootstrap also supplies buttons, alerts, forms and full templates, from a sign-in page to an entire website. You need only basic CSS knowledge to use it, but you are limited to the components it offers, and it may not have the one you need.

Logic

Choose by asking how much freedom you need against how fast you need to go. A one-off custom design points to vanilla CSS or utility classes. A standard-looking internal tool or prototype points to a component framework. For the same job, the number of lines you write goes down as you move from vanilla to utility to component, and the freedom goes down with it.

Pseudocode

GOAL: show a red "Report fraud" link, darker red on hover

OPTION 1: vanilla CSS
    write a rule: link is red and underlined
    write a second rule: link is dark red when hovered
    apply the class to the link

OPTION 2: utility framework (Tailwind)
    add classes straight on the link
        red text, underline, dark red on hover

OPTION 3: component framework (Bootstrap)
    add the single ready-made class "link-danger"

RESPONSIVE WIDTH with a utility framework
    default width = 64 pixels
    IF screen is medium or wider (768 pixels and up)
        width = 128 pixels
    IF screen is large or wider
        width = 192 pixels

DECIDE
    IF you want full control and have the time
        use vanilla CSS
    ELSE IF you want speed but still your own design
        use a utility framework
    ELSE IF you want speed and a standard look
        use a component framework

Tips for understanding the logic

  • Do the same small job three ways, like the danger link. Seeing the three versions next to each other is the quickest way to feel the difference.
  • Read utility classes literally. text-center centres the text. Most names say what they do.
  • A modifier prefix such as hover or md is a condition. Read it as "only when".
  • If a page loads slowly, long lists of utility classes and unused framework code are two places to look.
  • Frameworks like these are loaded from a link on the internet in the demos. No internet, no styles.
