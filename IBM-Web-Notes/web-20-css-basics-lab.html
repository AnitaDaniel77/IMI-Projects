Lab: CSS Basics, Styling Your Web Page

IBM HTML, CSS and JavaScript course, Module 2 hands-on lab. Code is in the web-20 files: solarsystem, inline-css, internal-css, external-css (with its CSS file) and converter (with its CSS file).

What the lab covers

Three jobs. First, style a Solar System page using all three ways of applying CSS. Second, practise each way on its own in three small files. Third, style the Unit Converter from the previous lab so it looks like a real app. The lab note says the styled converter files are reused in next week's lab on validating a JavaScript form, so keep both of them.

Part 1: the Solar System page

The page starts as plain HTML: a heading, an image, two paragraphs and a table. Styling is added step by step.

StepWay usedWhat changes
Heading fontInline, on the h1Font family set to cursive, then the font size set to 70 pixels
Page backgroundInline, on the bodyBackground colour set to wheat
Heading colourInline, on the h1Colour set with RGB values (139, 0, 0 is dark red)
Table bordersInternal, in a style block in the headOne rule gives the table, the header cells and the data cells a 2 pixel solid black border
Header row highlightInline, on the first rowYellow background on the whole row, so each header cell does not need its own style

Colours can be given as a name, or as RGB, HEX, HSL, RGBA or HSLA values. RGB mixes red, green and blue from 0 to 255, so rgb(0,0,0) is black and rgb(255,255,255) is white. A border needs a width, a style and a colour, and tables have no border until CSS adds one. Font family can be a generic family such as cursive, a named font such as Arial, or a list with fallbacks separated by commas.

Real-life example: this is a school notice board. Inline CSS is a coloured sticker on one notice. Internal CSS is the rule for the whole board ("every table has a black frame"). Setting colour on the row instead of each cell is like colouring the whole header line of a timetable at once.

Part 2: the three practice files

Inline: a blue centred heading and a green 18 pixel paragraph, with styles written in the style attribute. Internal: a style block that gives the h2 a Verdana font and a border, and the list items a blue 18 pixel font. External: a separate CSS file linked in the head, styling an h3 in dark green and a table with a black border and light blue background. The external version is the cleanest way and the one used for whole websites.

Part 3: styling the Unit Converter

The page is styled in layers, from the outside in. The HTML needed new class names so the CSS can find the elements.

AreaStyling decisions
Whole pageEvery element gets a 10 pixel margin and the page background is black
Home block (title and menu)A medium purple background that sits flush with the window edges (negative margins), with 1 cm of padding below. The title floats left in light purple at 30 pixels with 2 cm left padding. The menu floats right with 1 cm right padding.
Menu buttonsLight grey text on dark purple, 10 pixel margin and padding, tiny rounded corners (1 mm), 20 pixel text, no underline. On hover: white text, bolder weight, a purple background.
Conversion cardsEach one is a white 600 by 400 pixel card with a thick coloured top border (green for temperature, coral for weight, cyan for distance), rounded corners and flex display so the content sits centred
Inside a cardThe figure floats left at 200 pixels wide, the caption is black, 17 pixels and centred, the legend is 30 pixels and bolder
Convert buttons20 pixel text, light green, pill shape (40 pixel radius), 15 pixel side padding, and the cursor turns into a pointer on hover
Home iconA 40 pixel cyan circle fixed to the left edge, 40 pixels above the bottom of the window, so it stays put while scrolling
FooterLight pink background with a 20 pixel top margin

HTML changes needed: link the style file in the head; give the div in the nav the class topdiv; give the three menu buttons the class topmenu; give the three sections two classes each (b plus temperature, weight or distance); give the go-home div the class iconbutton. The b class holds what all three cards share, and the second class holds what is different. Note the lab's text has a typo, "temperatue".

My reading of the grid instruction: the lab says the conversion sections should be grid-based, with items centred. The cards themselves must be flex boxes, so I made the wrapper that holds the three cards the grid. That centres the cards on the page without breaking the floating title and menu in the home block.

Real-life example: this is the card layout of a banking app dashboard. The coloured top strip tells you which account type you are on, like the colour of a debit card. The floating home icon is the always-visible home button at the bottom corner of the app.

Logic

Style from general to specific. First the rules that apply to everything (margin, background). Then each big block (home, cards, footer). Then the small parts inside (buttons, captions, legends). Use a shared class for what repeats and a second class for what differs. For hover effects, write a second rule for the same element with the hover condition added.

Tips for understanding the logic

  • With a black page background, any text that has no colour of its own is black on black and looks missing. If something disappears, check its colour first.
  • Floated elements are taken out of the normal flow, so their parent can collapse to nothing. That is why my home block uses overflow hidden, which makes it wrap around its floats.
  • Fixed position is measured against the browser window, not the page. That is what keeps the home icon in place while you scroll.
  • Use units on purpose. Pixels are exact on screen, cm and mm are physical sizes, and percentages follow the parent.
  • Open the browser's dev tools, click an element and look at the Styles panel. It shows which rule applied, and which ones lost and were crossed out.
  • Do one card first, check it, then do the other two. A mistake in the shared b class affects all three cards at once.
