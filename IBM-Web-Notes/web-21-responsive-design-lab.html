Lab: Responsive Web Design with Tailwind and Bootstrap

IBM HTML, CSS and JavaScript course, hands-on lab. Code is in web-21-starter.html, web-21-tailwind.html and web-21-bootstrap.html.

What the lab covers

Responsive design means one page that adjusts to mobile phones, tablets and desktops, so it stays usable on all of them. The lab starts with a plain layout that is not responsive, then makes the same layout responsive twice: once with Tailwind CSS and once with Bootstrap. The layout has six parts: header, navigation bar, main section, aside, article and footer. Each part has its own background colour so the structure is easy to see.

Real-life example: a bank statement on your phone shows the account summary, then the transactions, then the offers, stacked one under the other. On a laptop the same three parts sit side by side. The menu on the phone folds into a hamburger icon. Same content, different arrangement.

Exercise 1: the starter page and why it fails

The starter uses plain CSS. The three middle parts sit in a row using flexbox, with fixed padding and no rules for narrow screens. Open it in the browser's developer tools with the device toolbar switched on (Ctrl+Shift+I, then Ctrl+Shift+M). Pick a phone size. The three parts stay squeezed in one row and can overflow, because nothing tells the page what to do on a small screen.

Exercise 2: Tailwind CSS

Tailwind is utility-first. Responsiveness comes from prefixes on the classes. A class with no prefix applies on every screen size. A class with the md prefix applies only from the medium breakpoint (768 pixels) upwards.

ClassesWhat they do
flex and flex-colTurn on flexbox and stack the children in a column
md and flex-rowFrom medium screens up, switch to a row, so the parts sit side by side
w-fullWidth 100% of the parent, so each part fills the screen on a phone
md and w-1/4From medium screens up, width 25%
flex-growThe main section takes all the space left over
p-4Padding of 1rem (16 pixels) on all sides
bg-red-500 and similarBackground colours
min-h-screenMakes an element at least as tall as the window (explained in the lab, but not used in its code)

Result: on a phone the aside, main section and article stack vertically. On a tablet or desktop they sit side by side with the main section in the middle.

Exercise 3: Bootstrap

Bootstrap gives ready-made components and a 12-column grid. A row holds columns, and each column says how many of the 12 columns it takes at each screen size. The page also needs Bootstrap's CSS and its JavaScript bundle, because the hamburger menu uses a small script to open and close.

ClassesWhat they do
col-12Full width on every screen, so the parts stack on a phone
col-md-3 and col-md-6From medium screens up: 3 of 12 columns (25%) for the aside and article, 6 of 12 (50%) for the main section
navbar and navbar-expand-lgA navigation bar that shows the links in a row on large screens and folds them into a hamburger button on smaller ones
navbar-toggler and navbar-toggler-iconThe hamburger button and its three-line icon
p-3Padding of 1rem on all sides
bg-danger, bg-primary, bg-warning, bg-successReady-made background colours

FeatureTailwind CSSBootstrap
ApproachUtility-first, allows full customisationPredefined components and styles

Real-life example: Tailwind is a box of building blocks that you assemble into your own design. Bootstrap is a set of prefabricated rooms that you place and join together.

Logic

Design for the smallest screen first. With no prefix, every element is full width and stacked. Then, at the breakpoint where there is room, add the side-by-side layout. In Tailwind that is the md prefix on the width and direction classes. In Bootstrap that is col-md-something next to col-12. The viewport meta tag in the head is what lets phones use their real screen width at all, so it must be there.

Pseudocode

START page
    head: tell the phone to use its real screen width (viewport setting)
    head: load the framework (Tailwind style file, or Bootstrap style file and script)

    header
    navigation bar
        IF Bootstrap
            large screens: links shown in a row
            smaller screens: links hidden behind a hamburger button
    middle area with 3 parts: aside, main section, article

    footer
END page

LAYOUT RULES for the middle area
    DEFAULT (phones)
        each part = full width
        parts stack top to bottom
    IF screen is 768 pixels or wider (medium)
        parts sit side by side
        aside = 25% wide
        main section = fills the rest (Tailwind) or 50% (Bootstrap)
        article = 25% wide

Tips for understanding the logic

  • Read prefixed classes as "from this size up". The md prefix on a width class means "from 768 pixels wide and larger, use this width".
  • The classes with no prefix are the phone version. Add the prefixed ones to grow the layout for bigger screens.
  • Test with the device toolbar in the browser and drag the width slowly. Watch for the exact point the layout flips. That point is the breakpoint.
  • If the layout looks desktop-sized on a phone, check for the viewport meta tag first.
  • Bootstrap columns in one row should add up to 12 or less. 3 plus 6 plus 3 is exactly 12.
  • Both frameworks load from the internet in these files. No connection means no styles.
