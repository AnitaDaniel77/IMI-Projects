1. Java follows strict grammar rules

class Greeting {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
    }
}
  • Think of syntax as language grammar
  • Classes are like book chapters
  • Braces {} group related instructions
  • Semicolons act like periods in sentences

Real-life example: every brace, semicolon, and keyword has a job - get the grammar wrong and Java simply won't understand you, the same way a missing full stop can make a sentence confusing.

2. Printing - System.out.println

System.out.println("Hello, Java!");
  • Think of it as a megaphone for your code
  • System.out.println is the megaphone
  • Code runs exactly as written - the computer follows your instructions literally
  • Text must be inside double quotes

3. Comments are notes

// This prints a greeting
System.out.println("Hello!");

/*
  This block explains
  the code below in detail.
*/
System.out.println("Done.");
  • Like sticky notes in a recipe - Java ignores these during execution
  • // for single-line notes
  • /* */ for longer explanations

Tip for reading code: when you open an unfamiliar file, read the comments first before the code itself - a good comment tells you what a block is trying to do, so you can then check whether the code actually does that, rather than reverse-engineering intent from raw logic alone.

4. Variables are labeled

type name = value;

int age = 25;
String name = "Sam";
double price = 9.99;
  • Give data a name to remember
  • Think of them as labeled jars
  • Declare the type, then the name
  • Assign values using the equals sign

5. Live coding - exploring variable scope

First version - a global (class-level) variable read from inside a method:

public class App {
    private static int session_id = 3;
    // "static" here = belongs to the class itself, not one
    // specific object - this is why every method in the class
    // can reach it without creating anything first

    public static void main(String[] args) throws Exception {
        CheckGlobal();
    }

    private static void CheckGlobal() {
        System.out.println(session_id);
        // reads session_id even though it was never passed in -
        // this works because session_id is declared OUTSIDE any
        // method, at class level, making it globally reachable
        // from anywhere inside this class
    }
}

Real-life example: a global/class-level variable is like a notice board pinned up in a shared office - anyone in that office (any method in the class) can walk up and read it without someone having to hand them a copy directly.

Hilbert's explanation, paraphrased: global scope means a variable can be accessed from anywhere within that class. He demonstrated that trying to re-declare a variable with the same name inside a smaller/inner scope (like inside an if block) when one with that name already exists at the outer scope causes a conflict - Java won't let you shadow it that way in the same block.

Tip for reading scope bugs: when you see "variable already defined" or similar errors, draw the braces { } on paper as nested boxes. Whichever box a variable is declared in, it's visible in that box and every box drawn inside it - but not outside it. This one visual trick solves most scope confusion.

6. Passing an object instead of relying on class-level state

var person = new Person(name: "Hilbert", Roles.LECTURER);
person.updateRole(Roles.STUDENT);
CheckGlobal(person);
// person is now passed IN as a parameter, rather than
// CheckGlobal reaching out to a class-level variable itself

private static void CheckGlobal(Person person) {
    System.out.println(person.getName() + person.getRole());
}

This threw a real compile error in the session: Type mismatch: cannot convert from Enum to String - happened because updateRole expected an Enum (Roles) parameter, but somewhere in the call a String was passed instead.

Real-life example: passing the object in as a parameter is like handing someone the actual notice directly, instead of telling them "go check the board" - more explicit, and it's now clear exactly what data the method is working with.

Tip for reading type-mismatch errors: these almost always tell you two things directly in the error text - what type was expected, and what type was actually given. Read those two words first before reading anything else in the stack trace; the fix is usually just making the two sides match.

7. While loop - counting

int count = 0;
while (count <= 5) {
    System.out.println(count);
    count++;
}

Output: 0 1 2 3 4 5

Pseudocode:

set count to 0
WHILE count is less than or equal to 5:
    print count
    increase count by 1

Real-life example: a while loop is like a security guard doing rounds - "keep checking the door, and as long as the condition holds (still my shift), keep doing the round" - the loop only stops once the condition becomes false.

Tip for reading loops: trace it by hand with a small table - one column for the variable, one row per pass through the loop. Write down count's value before and after each line runs. This catches off-by-one errors (like <= vs <) faster than just reading the code silently.

A palindrome reads the same forwards and backwards (example given: "LEVEL" - L E V E L, length 5).

Final working version

private static boolean IsPalindrome(String s) {
    s = s.toLowerCase();
    // normalizes case first, so "Level" and "level" are
    // treated as equivalent

    int i = 0, j = s.length() - 1;
    // i = left pointer, starts at the beginning
    // j = right pointer, starts at the end

    while (i < j) {
        if (s.charAt(i) != s.charAt(j)) {
            return false; // mismatch found - definitely not a palindrome
        }
        i++; // move left pointer inward
        j--; // move right pointer inward
    }
    return true; // pointers met/crossed with no mismatches found
}

Pseudocode (as written live in the session):

When you receive a string of length n:
1. Create a left pointer that points at the beginning
2. Point at the end of the string (right pointer)
3. If the left character is not equal to the right character, return false
4. Else continue checking the next pair:
   increment left, decrement right, continue

Real-life example: the two-pointer technique is like two people starting at opposite ends of a line of people and walking toward each other, checking that each pair they pass matches - if any pair on the way doesn't match, the whole line isn't symmetric, and you can stop immediately without checking the rest.

Tip for understanding two-pointer problems generally: before writing any code, draw the string out with index numbers underneath each character, then physically mark where i and j start and which direction each one moves. This makes it obvious when the loop should stop (i < j) and prevents the classic off-by-one mistake of using i <= j or forgetting to move both pointers each iteration.
