How Java Works

What Java is

Java is one of the few full multipurpose heavyweight languages still in wide use today — the main other one being C++. It was built to be readable and writable by humans, even though the syntax looks strange at first. Think of it like learning a foreign language: strange grammar rules, but it's just a way of expressing an idea, same as English does.

The pipeline: .java → .class → running program

Java code doesn't run directly. It goes through stages:

  1. .java files — plain text files you write, using Java syntax. Could technically be written in Notepad, but you'll use VS Code.
  2. javac (the compiler) — part of the JDK (Java Development Kit). It turns your .java text files into .class files (binary). In Eclipse this happens automatically when you hit Run — you never call javac by hand. In VS Code it's the same: your Run button triggers this behind the scenes.
  3. .class files — one per class you write. Still not directly readable by your actual computer hardware.
  4. JVM (Java Virtual Machine) — a simulated computer (CPU + memory) that actually runs the .class file.

Real-life analogy

Imagine writing a recipe in English (.java file), then translating it into a universal cooking-symbol language every kitchen understands (.class file). Any kitchen anywhere — gas stove, electric stove, wood fire — can follow the symbol version without you rewriting the recipe for each kitchen type. That's the JVM: it lets the same .class file run unchanged on Windows, Mac, or Linux.

Why the JVM exists

Other languages like C++ compile straight to machine code for one specific computer type — change machine, recompile from scratch. Java avoids that by compiling to .class files that run inside the JVM instead of on the raw hardware. The JVM is the same "shape" everywhere, so the .class file behaves identically no matter what's underneath it.

Logic to hold onto

write .java (human-readable idea)
      |
   javac compiles it
      v
   .class (binary, one per class)
      |
   handed to the JVM
      v
   JVM runs it as an actual program

JRE vs JVM vs JDK — the pieces

  • JDK — the full toolkit for developers, includes javac (the compiler) plus everything needed to build Java programs.
  • JRE — the Java Runtime Environment. Installing it is what sets up and creates the JVM.
  • JVM — the actual "virtual computer" that executes your .class files.

Real-life analogy

JDK is the full workshop (tools to build the car). JRE is the fuel and ignition system that lets an existing car actually start. JVM is the engine itself doing the running.

One language, many targets

The core Java language stays the same whether you're targeting desktop, mobile (Android SDK), or embedded devices — only the JDK/JRE variant changes for the target platform. This course sticks to plain console-output programs using Java Standard Edition (SE), which is exactly what you need for the Capitec-context self-study goal: core language fundamentals, not platform-specific extras.
